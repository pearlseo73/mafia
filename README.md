# 🎭 화상 마피아 - AI 실험 레포지토리

화상 기반 마피아 게임(**사건파일601**) 프로젝트의 **AI 기능 검증·프로토타이핑** 저장소입니다.

> 📌 이 레포는 **AI 파트 담당자의 실험 공간**입니다.
> 팀 전체 프로젝트(프론트·백엔드 포함) 레포지토리는 추후 별도로 생성됩니다.
> 여기서는 게임에 넣을 AI 기능들이 **실제로 구현 가능한지** 를 먼저 검증하고, 설계를 문서로 남깁니다.

## 🎯 AI 기능 목록

| 기능 | 설명 | 실행 위치 |
|---|---|---|
| 📰 **조간신문** | 낮 토론 STT 로그를 요약해 아침 기사 자동 발행 | 서버 (LLM) |
| ⚖️ **AI 심판** | 발언을 분석해 마피아 의심도가 가장 높은 플레이어를 처형 | 서버 (LLM, 스트리밍) |
| 🔍 **진술대조권** (아이템) | 지목한 플레이어의 발언 간 모순·회피 탐지 (시민 전용) | 서버 (LLM) |
| 🏷️ **키워드 뽑기** (아이템) | 지목한 플레이어의 발언에서 핵심 키워드 추출 | 서버 (LLM) |
| 😰 **얼굴/표정 분석** | 최후 변론 중 표정 기반 **"AI 동요 지수"** 표시 (연출용) | **브라우저** |
| 🏆 **칭호 부여** | 게임 종료 후 플레이 기록을 분석해 플레이어별 칭호 수여 | 서버 (LLM) |

> ⚠️ 표정 기반 지표는 **오락용 연출**이며, 과학적 거짓말 탐지가 아닙니다.

## 🏗️ 확정 기술 스택

**Python 서버는 사용하지 않습니다.** AI 기능은 브라우저(Vue)와 백엔드(Spring Boot)에 나누어 구현합니다.

| 영역 | 기술 | 위치 |
|---|---|---|
| STT (음성→텍스트) | **Web Speech API** (브라우저 내장) | Vue |
| 얼굴/표정 분석 | **face-api.js** (`@vladmandic/face-api`), 필요 시 MediaPipe Tasks JS | Vue |
| LLM 로그 분석 | **GPT 모델** (GMS LLM API 경유) | Spring Boot |
| 발화 로그 캐시 | **Redis** (ZSET, TTL) | Spring Boot |
| 미디어 전송 | **LiveKit SFU** (WebRTC) | — |
| 실시간 통신 | **WebSocket** | — |

```
사용자 브라우저
 ├─ Web Speech API ──── 발화 텍스트 + 시각 ──► Spring Boot ──► Redis (발화 로그)
 ├─ face-api.js ─────── 동요 지수 ──────────► Spring Boot ──► 전원 브로드캐스트
 └─ LiveKit Client ──── 미디어 ────────────► LiveKit SFU (Spring Boot 미관여)

Spring Boot ──► GMS (LLM API) / GPT 모델
                  └─ 조간신문 · AI 심판 · 진술대조 · 키워드 · 칭호
```

- **얼굴 분석은 서버를 거치지 않습니다** (명세 19-3) → 실시간성 확보
- **LLM 호출은 국면 전환 시점**(투표 시작 / 심판 / 게임 종료)에 집중 → 비용 관리
  - 예외: 아이템 2종은 토론 중 호출 → 지연이 유저에게 직접 노출됨

## ⚠️ 최대 기술 리스크

**브라우저 STT와 LiveKit이 마이크를 동시에 사용할 수 있는가.**

`webkitSpeechRecognition`은 `getUserMedia` 스트림과 별개로 자체 마이크에 접근합니다. 대부분 환경에서 동시 동작하지만 일부 기기에서 충돌·에코·인식률 저하가 보고됩니다.

**실패하면 조간신문·AI 심판·아이템 2종·칭호 부여가 전부 무너집니다.** → 최우선 PoC 대상

그 외 Web Speech API 제약:

- **Chrome/Edge 전용** (Firefox 미지원, Safari 부분 지원)
- 오디오가 **구글 서버로 전송**됨 (온디바이스 아님) → 개인정보 고지 필수
- `continuous` 모드도 자동 종료 → `onend` 재시작 루프 필요
- 발화 시각은 `onresult` 시점 기준으로 수백 ms~1초 지연 (신문·분석 용도로는 충분, 발화 감지용으로는 부적합)

**폴백:** Web Speech API가 실패해도 Python은 필요하지 않습니다. 오디오 청크를 Spring Boot로 올려 **Whisper API(HTTP)** 로 전사하면 됩니다. 지연·비용은 늘지만 스택 구조는 유지됩니다.

## ⚖️ 개인정보 / 윤리 유의사항

- 얼굴·음성은 **생체정보**로 개인정보보호법 적용 대상 → 수집·이용 **동의 절차 필수**
- STT 오디오가 외부(구글) 서버로 전송되는 사실을 **명시 고지**
- 발화 원문은 **Redis에만** 보관하고 TTL로 소멸 → MySQL에는 집계 결과만 영구 저장
- 밤 마피아 발화는 **별도 키로 격리**하여 낮 기능(신문·심판·아이템)이 접근할 수 없게 함
- 표정 지표는 "연출용"임을 UI에 명시하고 실제 진실 판정으로 오인되지 않게 할 것
- 테스트용 얼굴·음성 파일은 공개 저장소에 올리지 않도록 주의 (`.gitignore` 권장)
