# API 명세 참고 사항

> 최종 수정: 2026-07-26
> 대상: 팀 API 명세서 작성자 · 백엔드 담당
> 상세 계약: [AI-API명세.md](AI-API명세.md)

[AI-API명세.md](AI-API명세.md)를 팀 API 명세서에 반영할 때 **놓치면 문제가 되는 항목**만 뽑았다.
경로·이벤트 네이밍은 팀 컨벤션에 맞춰 바꾸되, 아래 내용은 그대로 지켜야 한다.

---

## 1. 전체 규모

| 구분 | 개수 |
|---|---|
| REST | **4개** |
| WS 클라이언트 → 서버 | **2개** (`speech.utterance`, `face.agitation`) |
| WS 서버 → 클라이언트 | **10개** (신문 2 · 심판 4 · 아이템 결과 · 얼굴 · 칭호 · 시스템 알림) |

AI 기능은 대부분 **서버가 밀어주는 것**이라 REST가 적다. 상태 변경 + 즉시 성공/실패 판정이 필요한 두 개(아이템 사용, 신문 Apply)만 REST이고 나머지는 WS다.

| Method | Path | 용도 |
|---|---|---|
| `POST` | `/rooms/{roomId}/items/{itemCode}/use` | AI 아이템 사용 |
| `PUT` | `/rooms/{roomId}/newspaper` | 조간신문 Apply |
| `GET` | `/rooms/{roomId}/result` | 결산(칭호) 조회 |
| `GET` | `/rooms/{roomId}/snapshot` | 재접속 복구 |

## 2. 명세서에 반드시 박아야 할 것 4건

### 2-1. 클라이언트가 보내지 않는 필드를 명시

`playerId` · `phase` · `round` · 역할은 **서버가 세션·게임 상태에서 유도**한다.

특히 **`phase`가 중요하다.** 클라이언트가 phase를 지정하게 하면 **밤 발화를 낮 발화로 위장해 공개 로그에 심을 수 있다.** 그러면 조간신문이 마피아 대화를 인용해 마피아를 노출시킨다.

`playerId`를 클라이언트가 보내게 하면 타인 명의로 발화를 위조할 수 있다.

### 2-2. "즉시 ack + 비동기 결과" 패턴

AI 아이템 사용은 수락만 즉시 응답하고, 분석 결과는 WS로 나중에 도착한다.

```http
202 Accepted
{ "requestId": "req_a1b2", "status": "PENDING", "estimatedMs": 4000 }
```

**이 패턴이 명세에 없으면 프론트가 로딩 UI를 설계할 근거가 없다.** `estimatedMs`는 그 표시용이다.

### 2-3. 모든 서버→클라이언트 이벤트에 "수신 대상" 컬럼을 둔다

여기가 틀리면 게임이 깨지는 게 아니라 **정보가 유출된다.**

| 이벤트 | 수신 대상 |
|---|---|
| `newspaper.preview` | **마피아만** (명세 17-3) |
| `item.analysis.result` | **아이템을 사용한 본인만** ([T6 확정](결정필요사항.md)) |
| 그 외 | 전원 |

### 2-4. `hasFindings: false`는 정상 응답이다

"모순이 발견되지 않았습니다" / "분석할 발언이 부족합니다"를 에러로 처리하면 프론트가 에러 토스트를 띄운다. 이건 **환각 방어의 정상 경로**이므로 `200`으로 내려야 한다.

## 3. 설계 포인트 2건

### 3-1. 칭호는 `game.ended`와 `game.titles`를 분리한다

칭호를 기다렸다가 함께 보내면 **결산 화면 진입이 2~5초 늦는다**(LLM 호출). 승패·역할을 먼저 띄우고 칭호만 나중에 채우면 로딩이 체감되지 않는다.

같은 이유로 `GET /rooms/{roomId}/result`에도 `titlesStatus: PENDING | READY | FAILED`가 필요하다.

### 3-2. 재접속 스냅샷에 AI 필드가 들어가야 한다

명세 3-3(재접속 복귀)에서 진행 중이던 심판 텍스트 · 내가 받은 분석 결과 · 신문이 복구되지 않으면 **재접속한 사람만 화면이 빈다.**

**`newspaper.content`는 요청자의 역할과 현재 phase에 따라 응답이 달라져야 한다.** 밤에 시민이 조회하면 `null`이어야 하고, 이걸 놓치면 **스냅샷 API가 유출 경로가 된다.**

## 4. 백엔드 담당자에게 먼저 확인할 것

### 4-1. WS 개별 전송이 가능한 구조인가 (선결 조건)

`item.analysis.result`(본인만)와 `newspaper.preview`(마피아만)가 여기 걸려 있다. STOMP `user destination`을 쓰는지, 세션 레지스트리를 직접 관리하는지에 따라 AI 파트 구현이 달라진다.

**브로드캐스트만 가능한 구조면 이 두 기능이 성립하지 않는다.**

밤 마피아 채팅(명세 21-2)·유령 채팅(15-2)도 같은 문제이므로 백엔드에서 이미 해결 중일 가능성이 높다. 방식만 확인하면 된다.

### 4-2. 서버 내부 phase 전환 훅

API가 아니라 **서버 내부 이벤트**다. AI 모듈이 아래 시점을 구독해야 한다.

| 시점 | AI 동작 |
|---|---|
| 낮 투표 시작 | 조간신문 생성 (명세 17-1) |
| AI 심판 확정 | 심판 LLM 호출 |
| 밤 시작 | 마피아에게 신문 push |
| 낮 시작 | 전원에게 신문 publish |
| 게임 종료 | 칭호 생성 |

### 4-3. 게임 상태 조회 인터페이스

칭호 지표 집계와 결과 검증에 필요하다.

- 생존자·역할 목록
- 라운드별 투표 내역 (팀킬 횟수·투표 적중률 산출용)
- 아이템 사용 이력
- 사망 이벤트 (라운드·원인)

## 5. 미확정 사항이 API에 미치는 영향

[결정필요사항.md](결정필요사항.md)의 결론에 따라 계약이 달라지는 항목이다.

| 결정 항목 | 영향받는 API | 상태 |
|---|---|---|
| **T6** 분석 결과 공개 범위 | `item.analysis.result` 수신 대상 | **✅ 확정 — 본인만.** 명세서에 그대로 표기 가능 |
| **T7** LLM 호출 중 국면 전환 | 아이템 롤백 여부, `AI_UNAVAILABLE` 처리 | 미확정 |
| **T8** 잔여 시간 부족 시 차단 | `ITEM_TIME_INSUFFICIENT` 에러 코드 존재 여부 | 미확정 |
| **T10** 얼굴 분석 계산 주체 | `face.agitation` C→S 발신자 검증 규칙 | 미확정 |
| **T11** 심판 LLM 실패 폴백 | `judgment.failed` 페이로드 | 미확정 |

**미확정 항목은 명세서에 확정 표기하지 말 것.** 먼저 박아두고 나중에 뒤집으면 프론트·백엔드가 이미 구현한 것을 되돌려야 한다.
