# Spring AI 이식 키트 — log_prompting.ipynb → 팀 백엔드 레포

> 작성: 2026-07-31
> 원본: [log_prompting.ipynb](log_prompting.ipynb) (노트북이 정본이다)
> 코드 스타일 원본: `reference/spring-ai-tool_완성본` (강사님 예제, git 미커밋)

노트북에서 확정된 **AI 기능 5종의 로직·프롬프트·검증 규칙**을 팀 백엔드 레포에서 Spring AI 로 다시 쓸 때 필요한 것만 모았다. 이 폴더를 그대로 팀 레포 옆에 두고 작업한다.

**노트북이 정본이다.** 이 폴더는 노트북에서 뽑아낸 스냅샷이고, 노트북이 바뀌면 어긋난다. 프롬프트와 렌더 스냅샷은 **손으로 옮겨 적지 않고 노트북 셀을 그대로 실행해 추출**했다.

---

## 0. 폴더 구조

```
SpringAI이식/
├─ README.md              ← 지금 이 파일. 이식 순서
├─ 00-코드스타일.md        ← 어떻게 쓸 것인가 (강사님 예제 기준) · 🔴 .st 함정
├─ 01-공통.md              ← 5기능이 공유하는 것 — 조회·컷오프·렌더 라벨·파싱·폴백
├─ 02-진술대조권.md         ┐
├─ 03-키워드뽑기.md         │
├─ 04-조간신문.md           ├ 기능별 이식 명세 (입력·렌더·프롬프트·검증·파라미터)
├─ 05-AI심판.md             │
├─ 06-칭호부여.md           ┘
├─ 07-검증체크리스트.md     ← 이식이 끝났는지 판정하는 기준
├─ log_prompting.ipynb    ← 노트북 사본. 프롬프트가 어떻게 나왔는지 원본이 필요할 때
├─ prompts/               ← 그대로 src/main/resources/prompts/ 에 복사한다 (10개)
├─ 렌더스냅샷/             ← 🔑 Java 렌더 결과와 문자열 비교할 기준값 (5개)
├─ fixture/               ← 테스트 입력 (발화 로그 · 게임 이벤트)
└─ 참고/                  ← AI 저장소 문서 사본 10개 (설계 근거 · API 계약 · TC 목록)
```

**폴더 째로 팀 레포에 넣어도 링크가 다 살아 있다.** AI 저장소 문서를 [참고/](참고/) 로 함께 넣었기 때문이다. 다만 **사본이라 갱신되지 않는다** — 정본은 AI 저장소에 있다.

`prompts/` 와 `fixture/` 만 실제 소스에 들어가고, 나머지 문서는 작업하는 동안 옆에 두고 보는 것이다.

## 1. 이식 순서 — 이 순서를 권한다

| 순서 | 기능 | 왜 이 순서인가 |
|---|---|---|
| ① | **공통 골격** ([01-공통.md](01-공통.md)) | `AiConfig` · 발화 조회 · 컷오프 · `PHASE_KO` · 프롬프트 로더. 다섯 기능이 전부 이것 위에 올라간다 |
| ② | 🔍 **진술대조권** ([02](02-진술대조권.md)) | **가장 검증이 많이 된 기능.** 입력이 가장 작고(535토큰) 출력이 JSON 한 줄이다. 환각 방어(번호 검증)·임계값·폴백이 다 들어 있어 나머지 기능의 본이 된다 |
| ③ | 🏷️ **키워드 뽑기** ([03](03-키워드뽑기.md)) | 진술대조와 입력이 거의 같다. ②를 복사해 시작한다. **알려진 결함이 있다** — 고치면서 옮긴다 |
| ④ | 📰 **조간신문** ([04](04-조간신문.md)) | 평문 출력이라 JSON 파싱이 없다. 대신 **밤 로그 유출 검사**와 2단 조립이 붙는다 |
| ⑤ | 🏆 **칭호 부여** ([06](06-칭호부여.md)) | 게임 이벤트 파싱이 필요하다. 게임당 1회 호출이라 지연이 문제되지 않는다 |
| ⑥ | ⚖️ **AI 심판** ([05](05-AI심판.md)) | **마지막.** `.stream()` 을 처음 쓰고 WS 이벤트 순서 보장이 얽힌다. 통계 6종 계산도 여기만 있다 |

②를 먼저 하면 ③~⑥에서 반복되는 것(프롬프트 로딩·`.options()`·파싱·폴백·검증 리턴 형태)이 한 번에 정해진다.

## 2. 먼저 읽을 것 3개

1. **[00-코드스타일.md](00-코드스타일.md) 의 `.st` 절** — `.st` 파일 10개 중 **SYSTEM 4개는 템플릿으로 렌더하면 깨진다.** 이걸 모르고 시작하면 원인을 찾는 데 시간이 든다
2. **[01-공통.md](01-공통.md) 의 "다섯 기능이 공유하는 4가지"** — 중복 구현을 막는다
3. **[07-검증체크리스트.md](07-검증체크리스트.md) 의 렌더 스냅샷 대조** — 이식이 맞았는지 **문자열 비교로 판정**하는 방법이다. 프롬프트가 한 글자 달라지면 노트북에서 잰 성적이 보장되지 않는다

## 3. 이 폴더의 핵심 — 렌더 스냅샷

[렌더스냅샷/](렌더스냅샷/) 의 5개 파일은 **노트북이 실제로 LLM 에 보낸 USER 프롬프트 전문**이다.

| 파일 | 조건 | 크기 |
|---|---|---|
| [진술대조-초코비-user.txt](렌더스냅샷/진술대조-초코비-user.txt) | 대상 초코비 · `now=21:11:05` | 513자 11줄 |
| [키워드-딸기우유-user.txt](렌더스냅샷/키워드-딸기우유-user.txt) | 대상 딸기우유 · `now=21:07:30` | 458자 15줄 |
| [조간신문-R1-user.txt](렌더스냅샷/조간신문-R1-user.txt) | R1 낮 → 제1호 | 1,729자 33줄 |
| [AI심판-R1-user.txt](렌더스냅샷/AI심판-R1-user.txt) | R1 심판 `21:03:39` | 2,400자 108줄 |
| [칭호-user.txt](렌더스냅샷/칭호-user.txt) | 게임 종료 | 4,894자 175줄 |

**Java 렌더가 이 파일과 글자 단위로 같으면 이식이 맞은 것이다.** LLM 을 부르지 않고도 판정된다 — 같은 픽스처를 넣고 렌더 결과를 이 파일과 `assertEquals` 하면 된다. 테스트를 하나 만들 값어치가 있는 유일한 자리다 (CLAUDE.md 의 "어서션 러너를 만들지 않는다"는 **LLM 출력**에 대한 규칙이고, 렌더는 결정적이라 해당하지 않는다).

이걸 통과시키지 않고 LLM 을 붙이면, 결과가 노트북과 달라도 **프롬프트 탓인지 렌더 탓인지 구분할 수 없다.**

## 4. 이식하지 않는 것

| | 왜 |
|---|---|
| 노트북의 파일 읽기 (`load_utterances`) | **Redis 조회로 바뀌는 자리다** → [01-공통.md](01-공통.md). 픽스처 로더는 `src/test` 에만 둔다 |
| 노트북의 `print` 출력·회차 루프 | 검증용이다. `RUNS=3` 는 사람이 눈으로 보려고 돌린 것이고 서비스는 1회 호출이다 |
| 밤 로그 파일 경로 | **조간신문의 유출 검사 전용**이고 프롬프트 입력에는 닿지 않는다. 그 외 어디에도 밤 로그를 읽는 코드를 만들지 않는다 |
| `reason` 필드를 프론트로 내리기 | 칭호의 `reason` 은 검증용이다. 실제 API 에서는 뺀다 (노트북 셀 5 주석) |

## 5. 이식하면서 함께 고쳐야 하는 것

노트북이 완성이 아닌 자리다. 그대로 옮기면 결함도 함께 온다.

| 기능 | 상태 |
|---|---|
| 🏷️ 키워드 뽑기 | 🔴 **evidence 오배정 결함이 살아 있다.** `by_id` 번호 검증·임계값이 없다 → [03 §7](03-키워드뽑기.md). 부분 문자열 검사는 **버리기로 확정** (§8) |
| 📰 조간신문 | 🔴 **결과 줄에 득표가 없어 헤드라인이 사실과 반대로 나온 회차가 있다** → [04 §8](04-조간신문.md) |
| ⚖️ AI 심판 | 스트리밍 미구현 (노트북은 `.call()` 로 받는다) → [05 §5](05-AI심판.md) |
| 🏆 칭호 부여 | **B 안(지표 매칭 + LLM 은 대사만)으로 확정** → [06 §8](06-칭호부여.md). **프롬프트와 출력 계약을 다시 써야 한다** — 노트북은 A 안이다 |
| 전체 | **생존 검사·아이템 소모·권한 검증이 없다.** 노트북에 게임 상태가 없어서다 |

### 확정된 결정 4개 (2026-07-31)

| | 결정 |
|---|---|
| `.st` 렌더 | **SYSTEM 은 문자열로 읽어 `.system(String)`, USER 만 `.param()` 렌더** → [00 §6](00-코드스타일.md) |
| 칭호 | **B 안** — 16종 고정 세트를 서버가 지표로 매칭, LLM 은 시상평만 → [06 §8](06-칭호부여.md) |
| 키워드 환각 방어 | **부분 문자열 검사 버림, `evidence` 번호 검증만** → [03 §8](03-키워드뽑기.md) |
| 조간신문 결과 줄 | **득표를 넣지 않는다.** 헤드라인이 틀릴 수 있는 것을 감수 → [04 §8](04-조간신문.md) |

### ⏸ 보류 항목 1개 — **STT 구현이 끝난 뒤에** 확인한다

| | |
|---|---|
| 시각 컷오프 (`t` 가 `HH:MM:SS` 문자열) | **자정을 넘기는 판에서 컷오프가 깨진다.** 지금은 노트북대로 문자열 비교로 가고, **프론트·백엔드의 STT 발화 수집 구현이 끝난 뒤에** Redis ZSET `score` 값을 확인해서 AI 쪽 컷오프만 전환한다 → **[01-공통.md 보류 항목](01-공통.md)** |

**지금 손대지 않는 이유** — 프론트·백엔드에 이미 넘긴 인수인계를 바꾸지 않기로 했고, **계약을 바꾸지 않고 나중에 AI 쪽만 고칠 수 있는 문제**다. 이식 코드를 쓸 때는 노트북과 똑같이 문자열 비교로 두면 된다.
