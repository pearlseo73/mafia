## 🔜 내일 첫 작업 — 진술대조권 구현

키워드 뽑기와 같은 구조로 만들면 된다. **다만 이 기능은 그냥 하면 실패할 것이 이미 확인됐다** (아래 🔴 참조).

### 키워드 뽑기와 다른 점 네 가지

1. **로그 범위가 전체 라운드다.** `UtteranceLog.forStatementCompare(speaker, usedAt)` 가 이미 있다
2. **발화에 번호를 매겨서 넣는다.** `u1 [R1] 발화내용` 형태 — `UtteranceLog` 에 렌더러를 추가해야 한다. **라운드 표시가 필수다** (§🔴)
3. **환각 방어 방식이 다르다.** 키워드는 부분 문자열 검사였지만, 진술대조는 **LLM 이 발화 번호만 반환**하고 서버가 원문으로 치환한다. 없는 번호(`u99`)는 서버가 버린다
4. **모델이 `gpt-5.4-mini`다.** 호출 시 `.options()` 로 덮어쓰고, `max-tokens` 가 아니라 **`max-completion-tokens`** 를 써야 한다 (아니면 HTTP 400)

### 검증할 것 — [기대답안](../log_analysis/expected/진술대조-기대답안.md) 참조

- **TC-1** 박도현 R3 `21:11:05` 지목 → `u2`·`u6`·`u9` 3단 모순을 다 잡는가
- **TC-2** 같은 라운드 자기모순 `u8` ↔ `u9`
- **가장 중요한 실패 조건: `u5`("마음이 바뀐 겁니다")를 모순으로 잡으면 안 된다.** 그건 의견 변경 해명이지 모순이 아니다
- **TC-5** 김서준 지목 → "모순 없음"을 정직하게 답하는가. 새 근거로 판단이 바뀐 것을 모순으로 잡으면 실패
- **TC-4** 최지우 → 발화 부족으로 LLM 미호출

### 🔴 미리 알아둘 것 — 기본 프롬프트로는 실패한다

파이썬으로 세 발언만 **라운드 표시 없이** 주고 물었을 때 `gpt-5.4-mini` 가 이렇게 답했다.

> "모순은 아니며, u2와 u3는 강예린을 믿거나 의심하지 않았다고 말할 뿐이고 u1은 강예린이 수상하다고 말해 서로 직접 충돌하지 않습니다."

**"모순이 아니다"로 판정했다.** 원인 추정 두 가지.

1. **라운드 정보가 없어서** `u2`·`u6`("처음부터 믿었다")가 *과거에 대한 주장*임을 알 수 없었다
2. [프롬프트](../log_analysis/prompts/진술대조.md)의 **System 규칙 4**("생각이 바뀔 수 있는 의견 변화와 과거를 다르게 진술하는 것은 다르다")를 안 넣었다

→ 이 두 개가 진술대조권 프롬프트의 핵심이다. 통과하지 않으면 여기부터 손본다.

## 결정이 필요한 것

### 게임 기획 쪽

- **R1 토론에서 진술대조권을 막을지** — 임계값(3건·40자) 기준으로 R1 토론 종료 시점에 6명 중 3명이 미달이고, 통과해도 대조할 이전 라운드가 없다. 버튼을 비활성화할지, 눌리게 두고 "발언 부족"으로 아이템을 소모시킬지(후자는 아이템 낭비)
- **투표 내역을 진술대조 프롬프트에 넣을지** — 체크리스트 TC-3(말과 행동 불일치)은 발화 로그만으로는 검출 불가능하다. v0 에서는 넣지 않음
- **대화 맥락을 넣을지** — 대상 1명의 발화만 주면 "회피" 탐지가 안 된다. [§7-1](AI기능-구현설계.md)은 목적을 "모순·**회피**"로 적고 있다. v0 에서는 모순만 봄
- **첫 호출 워밍업을 둘지** — 아이템 2종은 토론 중 호출이라 첫 호출 4~7초가 유저에게 그대로 보인다. [T8](결정필요사항.md) 임계값과 함께 결정

### 픽스처 정리 — 기대답안 확정 전에 필요

- **체크리스트 TC-8 의 근거 발화 하나가 사용 시각 이후다.** `21:02:58` "근거도 없이"는 아이템 사용(`21:02:09`) 다음이라 입력에 들어갈 수 없다 → 근거 목록을 3개로 수정
- **`몰아가기` 가 강예린의 발화에 없다.** 정민재가 `21:02:45` 에 결과로 공유하는 단어인데 원문에 없다. **픽스처 오류인지, 정민재가 결과를 왜곡해 전달한 것인지** 정해야 한다. 후자면 [로그2안아이디어.txt](../log_analysis/scenario/로그2안아이디어.txt)의 "아이템 사용 결과 왜곡"이 1안에 이미 심긴 셈이고, 강예린의 `21:07:25` 대사와 앞뒤가 맞는다

### 명세 수정

- **명세 17-2 를 1000자 → 500자로** (백엔드가 임의로 적은 값이었다)
- **[AI-API명세.md](AI-API명세.md) §2-5 보강** — `contradictions[].quote` 가 LLM 출력이 아니라 **서버 조립 결과**임을 명시

### GMS 관련

- **`temperature` 가 실제로 반영되는지** — `gpt-5.4-mini` 에 넣어도 400 이 아니지만(강사님 주석과 다름) 무시될 수 있다. 칭호·신문의 다양성이 달라지는지 비교 필요
- **기능별 토큰 상한 값** — 전역값 하나로는 조간신문과 키워드 뽑기를 동시에 만족시킬 수 없다
- **`response_format`(json_schema) 지원 여부** — 지원하면 프롬프트 대신 API 레벨로 출력 형식 강제 가능

## 확정된 사실 (참조용)

- **AI 심판 모델 = `gpt-5.4-mini`** — reasoning 모델의 "스트리밍 초반 침묵" 우려가 실측에서 나타나지 않았다(첫 글자 1.13초)
- **`gpt-5.x` 는 `max_tokens` 를 쓰면 HTTP 400** — `max_completion_tokens` 필수
- **`GET /models` 미지원** — 모델명을 API 로 발견할 수 없다. 확인된 것은 `gpt-4o-mini`, `gpt-5.4-mini`
- **조간신문 500자, 짧게만 보여주는 것은 의도된 설계** — 천천히 읽으면 게임이 쉬워진다. 프롬프트에 "중요한 정보를 앞쪽에 배치"를 지시해야 한다
- **코드 스타일** — Lombok 사용, 패키지는 도메인별, `ChatClient` 는 빈 주입, LLM 출력 계약은 `record`, 프롬프트는 `.st` → [개발환경 §4-1](개발환경.md)
- **환각 방어는 기능마다 다르다** — 진술대조는 발화 번호 반환, 키워드는 부분 문자열 검사
