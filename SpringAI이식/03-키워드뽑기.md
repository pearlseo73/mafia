## 1. 진술대조권과 무엇이 다른가

| | 키워드 뽑기 | 진술대조권 |
|---|---|---|
| 입력 화자·시점 | **같다** (대상만 · 사용 시각 이전) | 같다 |
| 렌더에 `phase` | ❌ **넣지 않는다** | ✅ 필수 |
| 번호 폭 | `u1` — 정렬 없음 | ` u1` — 폭 3 오른쪽 정렬 |
| 개수 요구 | **"반드시 5개"** | "두 개" |
| 모델 | `gpt-4o-mini` / `maxTokens` | `gpt-5.4-mini` / `maxCompletionTokens` |
| 번호 검증 | ❌ 없다 → **붙일 것** | ✅ `byId` 밖은 버림 |
| 임계값 | ❌ 없다 → **붙일 것** | ✅ 3건 · 40자 |
| 원문 치환 | ❌ 없다 | ✅ 번호 → 원문 |
| 프롬프트 규칙 수 | 6개 + 핵심 규칙 블록 | 3개 |
| 역할 제한 | 전원 사용 가능 | 시민 전용 |

**`phase` 를 넣지 않는 이유** — 반복 횟수에는 어느 시점인지가 필요 없고, 라운드만 있으면 '라운드별 반복'이 보인다.

**진술대조는 규칙을 12개에서 3개로 줄여 성적이 좋아졌다. 키워드는 아직 안 줄였다** — 줄일 후보다.

---

## 2. 입력

| | |
|---|---|
| 화자 | 지목 대상만 |
| 시점 | 아이템 사용 시각 이전 (`now` 자체 제외) |
| 라운드 | **제한 없음** — 게임 처음부터 (2026-07-28 명세 변경. 전에는 현재 라운드만) |
| 프롬프트에 넣는 값 | 대상 닉네임 · **현재 시점** · 번호 붙인 발화 목록 |

**라운드를 제한하지 않는 이유** — 반복을 세는 기능이라 범위가 좁으면 5개를 채울 수 없다.

> 로그 범위를 전체로 넓히면서 **진술대조권과 입력이 같아졌다.** 산출물(키워드 vs 모순)로만 구분되는 셈이다. 아이템 차별화 근거를 다시 볼 필요가 있다 → [AI기능-구현설계 §7-1](참고/AI기능-구현설계.md).

진술대조와 달리 **현재 시점(`now`)을 프롬프트에 넣는다.** USER 템플릿의 `{now}` 자리다.

## 3. 렌더

```
u1 [R1] 저는 그런 거 시간 남비라고 생각해요 그냥 느낌으로 가야죠
u2 [R1] 아니 그러면 3년 동안 뭘 어떻게 하겠다는 거예요 근데 신이라고 할 거잖아요
...
u11 [R2] 그 결과 아무도 못 봤죠 혼자만 봤다고 하는 거잖아요
```

`u{n} [R{round}] {text}` — **번호 정렬 없음, 페이즈 없음, 시각 없음, 화자 없음.** 라운드만 붙인다.

USER 전체 형태는 [렌더스냅샷](렌더스냅샷/키워드-딸기우유-user.txt) 을 본다 (`분석 대상` · `현재 시점` · `발언 목록 (시간순):` 머리글이 붙는다).

## 4. 프롬프트가 요구하는 것

### 핵심 규칙 — 표현이 아니라 의미로 묶는다

이게 이 프롬프트의 본체다. 글자가 다른 발언이라도 같은 태도·주장이면 하나로 묶어 센다.

```
"시간 낭비다" / "삼분 동안 뭘 하겠나" / "방식이 비효율적이다"  →  하나의 키워드, count 3
```

**글자가 같은 반복만 세면 5개를 채울 수 없다.**

### 나머지 규칙 6개

1. **반드시 5개.** `count` 큰 것부터
2. `keyword` 는 **주어진 발언에 실제로 나온 말에서** 고른다. 10자 이내
3. **사전형으로 다듬는다** (`억울하면` → `억울하다`). 다만 어미까지만 — 요약 라벨(`소극적 태도`, `근거 없는 주장`) 금지
4. 누구나 쓰는 말(`그러니까`, `저는`) 금지
5. 마피아 추측 금지
6. JSON 형식으로만

**규칙 3의 경계가 중요하다** — `억울하면 → 억울하다` 는 같은 말을 다듬은 것이고 `소극적 태도` 는 없던 말을 만든 것이다. 이전 버전에서 **5개 중 4개가 발화가 아니라 분석관이 붙인 라벨**이었다. 좋은 예·나쁜 예를 짝으로 넣으면 걸러지고, 규칙만 쓰면 지켜지지 않는다.

이게 문제인 이유 — 키워드 뽑기의 값어치는 **"그 사람이 실제로 한 말"** 을 보여주는 데 있다. `소극적 태도` 는 AI 의 판단이지 증거가 아니고, 유저는 반박할 방법도 없다.

## 5. 출력 계약

```jsonc
{"keywords": [{"keyword": "시간 낭비", "count": 3, "evidence": ["u1", "u2", "u3"]}]}
```

- `count` — 그 의미가 등장한 발언 수
- `evidence` — 근거가 된 발언 번호. **주어진 번호 안에서만**

## 7. 🔴 이식하면서 고칠 것

딸기우유 11건(`now=21:07:30`) 결과를 원문과 대조한 것이다.

```
시간 낭비     count=3  ['u1', 'u3', 'u2']    ← 묶기 정확
근거 없다     count=2  ['u6', 'u3']          ← u3 재사용, 오배정
숨길 게 없다   count=1  ['u5']
억울하다      count=1  ['u4']
비효율적이다   count=1  ['u3']                ← u3 세 번째, 시간 낭비와 같은 묶음
```

- **`u3` 하나가 세 키워드에 배정됐다.** `u3`("방식이 비효율적이라고 한 거잖아요")에는 근거 얘기가 없는데 `근거 없다` 의 evidence 로 들어갔다. 실제 근거는 `u6` 하나뿐인데 `count=2` 다
- **`비효율적이다` 는 `시간 낭비` 와 같은 묶음이어야 한다.** 프롬프트가 예시로 명시한 묶음인데 분리됐다
- 원인은 **5개 강제**로 보인다. 태도가 드러나는 발화가 5개가 안 되는데 5개를 요구하니 이미 쓴 발화를 재사용한다
- **R2 발화 3건(`u9`·`u10`·`u11`)이 evidence 에 하나도 안 쓰였다.** 로그 범위를 전체 라운드로 넓힌 목적이 반쯤 안 살았다

### 붙일 순서 — 진술대조 ②·④를 그대로 옮기면 된다

1. **`byId` + 번호 검증** — evidence 로 원문을 찍어주면 오배정이 눈에 보인다
2. **evidence 중복 배정 검사** — 같은 번호가 여러 키워드에 들어갔는지
3. **`count == evidence.size()` 검사** — 위 결함이 1·2·3만으로 자동으로 걸린다
4. **임계값** (TC-9) — 진술대조의 3건·40자와 같은 계열
5. `phase` — 필요해지면. 지금은 넣지 않는 것이 설계다

**부분 문자열 검사는 붙이지 않는다** → §8.

### "반드시 5개" 를 줄이는 것도 후보다

원인이 5개 강제라면 **개수를 3~5개로 되돌리는 것이 검증을 늘리는 것보다 먼저다.** CLAUDE.md 의 "여러 개를 요구하면 흔들린다. 개수를 줄이는 것이 조합을 코드로 옮기는 것보다 먼저다"가 그대로 적용되는 자리다. 다만 명세가 5개라 게임 기획과 함께 정해야 한다.

## 8. ✅ 환각 방어 — 부분 문자열 검사는 버리고 번호 검증만 남긴다 (2026-07-31)

### 먼저 — 이건 밤 로그 유출과 다른 문제다

둘을 섞으면 판단이 어긋난다.

| | 막는 것 | 피해 |
|---|---|---|
| **밤 로그 유출 방어** (절대 규칙 1) | 밤 발화가 입력·출력에 섞이는 것 | **마피아 신원 노출** — 게임이 즉시 끝난다 |
| **키워드 환각 방어** | 모델이 **대상이 하지 않은 말**을 키워드로 내는 것 | **유저가 없는 발언을 근거로 사람을 의심한다** |

**밤 로그를 아예 안 주는 것으로 첫째 문제는 끝난다.** 그런데 둘째는 남는다 — 입력이 100% 낮 공개 발화여도 모델이 그 발화에 **없는 표현**을 만들어낼 수 있다.

실제로 그랬다. 이전 버전에서 **5개 중 4개가 발화가 아니라 분석관이 붙인 라벨**이었다 (`소극적 태도`, `근거 없는 주장`). 이게 문제인 이유 — 이 아이템의 값어치는 **"그 사람이 실제로 한 말"** 을 보여주는 데 있다. `소극적 태도` 는 AI 의 판단이지 증거가 아니고, **지목당한 유저는 반박할 방법이 없다.**

### 결정 — 검사 두 종류를 갈라서 처리한다

| | 판정 |
|---|---|
| **키워드 문자열 부분 문자열 검사** | ❌ **버린다** |
| **`evidence` 발화 번호 검증** | ✅ **남긴다** |

**부분 문자열 검사를 버리는 이유는 정확도가 아니라 부작용이다.**

- `시간 남비`(STT 오인식)를 모델이 **`시간 낭비` 로 교정해서 내놓는다.** 사람이 봐도 그게 맞는 해석인데, 원문에 없으니 **정답이 버려진다**
- 프롬프트가 **어미를 다듬으라고 지시**한다. `억울하다` 는 `억울하면` 의 부분 문자열이 아니라 이것도 버려진다
- 즉 **프롬프트 규칙 3과 검사가 서로 싸운다.** 규칙을 지킬수록 검사에 걸린다

**번호 검증을 남기는 이유는 실측 결함이 이걸로 잡히기 때문이다.** §7 의 `u3` 오배정은 부분 문자열 검사로는 안 걸리고 번호 검증·중복 검사·`count` 일치로 걸린다. 이름을 "환각 방어"보다 **오배정 검사**로 부르는 편이 정확하다.

### 남기는 검사 4종

```
① evidence 번호가 byId 안에 있는가        (없는 번호 → 그 키워드를 버린다)
② 같은 번호가 여러 키워드에 배정됐는가     (u3 결함이 여기서 걸린다)
③ count == evidence.size()               (근거 없이 숫자를 부풀렸는가)
④ 키워드 5개가 다 왔는가 · 빈 항목이 없는가
```

**유저가 근거 발화 원문을 함께 보기 때문에 이것으로 충분하다.** 키워드가 조금 다듬어져 있어도 그 아래 실제 발화가 붙어 있으면 유저가 스스로 판단한다 — 검사가 못 잡는 것을 **UI 가 잡는다.**

> **진술대조와 일관된다** — 원문 인용을 금지하고 번호만 받는 쪽이 잘 작동했다. 키워드도 번호 검증에 무게를 둔다.

**주의:** `ai-lab` 옛 구현에는 부분 문자열 검사가 있다. **이식할 때 가져오지 않는다.**
