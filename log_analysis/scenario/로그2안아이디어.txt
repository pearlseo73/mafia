거짓 주장
- 특정 아이템 보유 여부
- 아이템 사용 결과 왜곡  ★ 게임상 가장 강력한 거짓말
    T6 확정으로 분석 결과는 사용자 본인만 본다 → 결과를 마음대로 바꿔 말할 수 있다
    1안 로그에 이미 암시됨: 강예린 "그 결과 아무도 못 봤죠 혼자만 봤다고 하는 거잖아요" (21:07:25)
    마피아가 진술대조권을 쓴 척하거나, 실제로 쓰고 결과를 반대로 전달하는 경우
- 발언 이력 거짓말 ("저 그런 말 안 했어요")  ← 진술대조권의 정면 타겟
- 투표 대상 거짓말 (말과 행동 불일치)  ← 1안에 이미 있음 (박도현 21:01:12 vs 실제 투표)
- 신문 내용 왜곡
    마피아만 밤에 신문을 본다(17-3) → 낮에 내용을 거짓으로 전달 가능
- 사망자 유언 왜곡 ("최지우가 죽기 전에 A를 지목했어요"가 사실과 다름)
- 방어권 허세 (실제로 없는데 있다고 주장해 AI 심판 회피를 유도)
- 역할 거짓말 (기본. 마피아가 시민이라 주장)


===============================================================
그 외 시나리오 축 후보
===============================================================

--- 1. 마피아 승 (명세 13-6: 마피아 수 == 시민 수) ---

1안은 시민 승이라 마피아 승 분기가 전혀 안 돌아간다.

검증 대상
  - 조간신문·칭호가 패배 팀 관점에서 어떻게 서술되는지
  - 게임이 짧게 끝날 때(2라운드 이내) 로그 부족 상황

잠금 해제되는 칭호 (칭호예시.txt)
  - 침묵의 암살자 (발화량 적은데 마피아로 승리)  ← 1안에서는 구조적으로 불가능
  - 완전범죄 (마피아인데 한 번도 최다 의심 대상이 안 됨)

우선도: 높음. 승패 축이 절반 비어 있다.


--- 2. 과묵한 판 + STT 오인식 (열악한 입력) ---

전원이 소극적이고 STT 인식률도 낮은 판. 실전에서 가장 자주 나올 상황이다.
(첫 판, 마이크 품질 나쁜 참가자, 서로 눈치만 보는 초반)

의도적으로 심을 것
  - 발화가 라운드당 5~6건뿐
  - 이름 오인식: 강예린 -> "강애린" / "강예 린", 박도현 -> "박또현" / "박 도현"
  - 문장 끊김: "저는 그러니까 어제" (중간에 인식 종료)
  - 동음이의 오인식: "시민" -> "시면", "마피아" -> "마피어"

검증 대상
  - 5개 기능 전부의 폴백 동작
  - 이름 오인식 시 화자 매칭 ("강애린"과 "강예린"을 같은 사람으로 볼지)
  - 발화 임계값 미달 시 LLM 호출 자체를 생략하는 로직

우선도: 최고. 실전 빈도가 가장 높고, 여기서 무너지면 다른 시나리오는 의미가 없다.


--- 3. 시민 자멸 / 마피아 방관 ---

마피아는 거의 말하지 않고, 시민끼리 격렬하게 싸워 서로를 처형하는 판.

검증 대상
  - AI 심판의 발화량 편향  ← 핵심
    LLM은 "말 많은 사람"을 마피아로 고르는 경향이 있다.
    조용한 마피아를 놓치고 시끄러운 시민을 처형하면 프롬프트를 고쳐야 한다.
  - 조간신문이 시민 간 갈등을 어떻게 서술하는지

잠금 해제되는 칭호
  - 역대급 억울함 / 무고한 희생양 (시민인데 의심을 가장 많이 받음)
  - 웅변가 (발화량 1위)
  - 의심 제조기 (가장 많은 사람을 의심)

우선도: 높음. AI 심판 품질을 좌우하는 편향 검증이다.


--- 4. 완벽한 거짓말쟁이 마피아 (모순 0) ---

마피아가 시민 논리를 완벽하게 흉내내고 진술에 모순을 만들지 않는 판.
위 "거짓 주장" 항목들을 여기에 몰아넣는다.

검증 대상
  - 진술대조권이 "모순이 발견되지 않았습니다"를 정직하게 답하는지
    ★ 실패 조건: 없는 모순을 만들어낸다
    1안은 "모순이 있는데 찾는가", 이 시나리오는 "없는데 안 만드는가"
  - 아이템 거짓 주장 검출 - 발화만으로는 불가능, ITEM_GRANT 대조가 필요
    -> 진술대조권 프롬프트가 아이템 보유 정보를 받을지 결정해야 함

잠금 해제되는 칭호
  - 소름 돋는 거짓말 (사실과 정반대지만 모두를 설득)
  - 완전범죄

우선도: 높음. 환각 방어의 반대 방향 검증이다.


--- 5. 의심 대상이 계속 바뀌는 판 ---

여론이 라운드마다 뒤집히고 플레이어들이 지목 대상을 자주 변경한다.

잠금 해제되는 칭호
  - 갈대왕 (의심 대상을 가장 자주 변경)
  - 뚝심의 추리왕 (처음부터 끝까지 같은 사람 지목)
  - 여론 장악자 (자신의 지목 이후 동일 지목이 증가)  <- 시계열 분석 필요
  - 국민 변호사 (다른 플레이어를 가장 많이 옹호)
  - 인간 확성기 (다른 플레이어 이름을 가장 많이 언급)

우선도: 중간. 칭호 전용 시나리오다. 다른 기능 검증 기여는 적다.


--- 6. 분기 모음 (1안에서 못 탄 명세 경로) ---

포함할 분기
  - 19-8 최후변론 부결 (찬성 과반 미달 -> 처형되지 않는 연출)
  - 21-5 마피아가 아무도 지목하지 않은 밤 -> 시민 사망 없음
  - 17-7 무사망 밤 -> 조간신문에 "평화로운 밤입니다"
  - 18-7 AI 위임 버튼 다수 사용 -> T4 집계 규칙 검증
  - 14-3/14-4 스킵 다수 -> 토론 조기 종료, 토론 로그가 짧게 잘림

우선도: 높음. 효율이 가장 좋다. 한 판으로 5개 분기를 덮는다.


--- 7. 공격적 발언·욕설 포함 ---

놓치기 쉬운 축. 마피아 게임은 실제로 공격적인 말이 나온다.

검증 대상
  - LLM이 조간신문·칭호 생성을 거부하거나 과도하게 순화하지 않는지
    ★ 실전에서 실제로 터지는 문제. "부적절한 내용이 포함되어" 같은 응답이 나오면
      게임이 멈춘다. 기사 톤이 갑자기 사무적으로 바뀌는 것도 실패다
  - 반대로 욕설을 신문에 그대로 인용하지는 않는지
  - 시스템 프롬프트로 톤을 고정할 수 있는지

우선도: 중간~높음. 데모 직전에 발견하면 대응할 시간이 없다.


--- 8. 유령 채팅 + 이탈/재접속 ---

죽은 사람의 발화(15-2 유령 채팅)와 연결 끊김 구간이 섞인 판.

검증 대상
  - 죽은 사람 발화가 공개 로그에 섞이지 않는지  <- 격리 축 하나 더
    (밤 마피아 로그와 같은 성격의 유출 경로)
  - 이탈 구간의 로그 공백 처리
    "A가 3라운드에 침묵했다"고 잘못 해석하면 칭호 지표가 틀어진다

우선도: 중간. 로그 격리 설계의 세 번째 축이다.


--- 9. 유사 닉네임 (화자 혼동) ---

"김서준 / 김서진", "이하윤 / 이하은" 처럼 비슷한 이름이 섞인 판.
명세 5-3은 완전 중복만 금지하므로 유사 이름은 실제로 가능하다.

검증 대상
  - 진술대조권·키워드 뽑기가 화자를 혼동하지 않는지
  - 2번(STT 오인식)과 결합하면 난이도가 크게 올라간다

우선도: 낮음~중간. 2번에 흡수시켜도 된다.

===============================================================
칭호예시.txt 검토 - 설계 함의
===============================================================

16개 칭호 중 상당수가 이벤트 로그만으로는 집계할 수 없다.

[이벤트 로그로 집계 가능]
  웅변가(발화량), 최고의 팀킬상(투표 내역+역할), 침묵의 암살자(발화량+승패),
  무고한 희생양·완전범죄(피지목 수+역할), 완벽한 추리·촉이 왔다상(투표 내역+역할)

[발화 내용 분석이 추가로 필요]
  인간 확성기    -> 이름 언급 횟수를 발화에서 세야 함
  의심 제조기    -> "누구를 의심했는지"를 발화에서 추출
  국민 변호사    -> "누구를 옹호했는지"를 발화에서 추출
  여론 장악자    -> 지목 발언의 시계열 + 이후 동일 지목 증가 추적
  갈대왕         -> 지목 대상 변경 이력
  뚝심의 추리왕  -> 지목 대상 고정 여부
  자백 직전상    -> "불리한 정보"를 판정해야 함
  소름 돋는 거짓말 -> 사실 대조 + 설득 성공 여부 판정
  역대급 억울함  -> 투표 외에 발화상 지목까지 세야 함

-> 함의: AI기능-구현설계 §5-2의 하이브리드 설계에 중간 단계가 하나 더 필요하다.

   [현재 설계]  서버 집계 지표 -> LLM이 칭호명·대사만 창작

   [보강 필요]  서버 집계 지표
                + 발화에서 "지목/옹호 대상" 추출 (LLM 또는 규칙)
                -> LLM이 칭호 배정 + 대사 창작

   투표는 라운드당 1회지만 발화상 지목은 수십 번 일어난다.
   추출을 LLM에 맡기면 라운드마다 호출이 필요하고,
   규칙(이름 매칭 + 부정/긍정 표현)으로 하면 정확도가 떨어진다.
   -> 별도 결정 사항. 어느 칭호를 실제로 넣을지 먼저 좁히는 게 순서다.
