## 2. 형태 — D안 타블로이드

### 골격

```
【601 조간】 제N호                        ← 머리글. 누가 쓸지 §7 미결 4

■ [사망자 — 서버 삽입]
■ [어제의 최대 사건 한 줄 — LLM]

[본문 3~4문단. 시간순. 발언 인용 2개까지. 논평하지 않는다 — LLM]

[마지막 문단으로 닫는다 — 내용은 §7 미결 2에 달려 있다]
```

**헤드라인 두 줄만 읽어도 성립해야 한다.** 낮 시작에 10초만 표시하고 닫기 때문이다(17-6).

### R2 신문 예시 (R1 낮 기반) — 446자

```
【601 조간】 제2호

■ 소금빵 님, 지난 밤 유명을 달리하다
■ "시간 낭비"라던 딸기우유 님, 하루 만에 최다 지목자로

"느낌으로 가야죠" — 딸기우유 님의 한마디에 회의장이 얼어붙었다. 곰돌이 님이
"그건 마피아가 제일 좋아하는 방식"이라 받아쳤고, 초코비 님은 곧바로 "제일
수상하다"며 손가락을 들었다.

밤하늘 님은 라면왕 님의 매끄러운 진행을 의심했고, 말 없던 소금빵 님도 그 시선을
피하지 못했다.

투표함이 열렸으나 셋이 나란히 섰다. AI 심판이 부른 이름은 초코비 님 —
그러나 폭탄은 터지지 않았다.
```

### R3 신문 예시 (R2 낮 기반) — 443자

```
【601 조간】 제3호

■ 밤하늘 님, 지난 밤 유명을 달리하다
■ 딸기우유 님 처형 — 마피아였다

어제 회의는 초코비 님에게서 시작됐다. 방어권으로 살아남은 그를 두고 곰돌이 님이
"어제는 딸기우유 님에게 투표한다더니 소금빵 님에게 넣었다"며 파고들었다.
초코비 님이 "처음부터 딸기우유 님을 믿었다"고 답하자 곰돌이 님은 "어제와 완전히
다르다"고 되받았다.

딸기우유 님은 아이템으로 라면왕 님의 입을 막았다. 곰돌이 님은 "이게 답"이라 했다.

표는 딸기우유 님에게 몰렸다. "저 죽으면 다음은 라면왕 씨예요" — 마지막 말을
남기고 그는 무너졌다.
```

**사건이 많은 라운드에서 톤이 더 잘 굴러간다.** 최후변론을 마지막 문장에 두면 극적으로 닫힌다.

### 폐기한 후보 — 왜 D를 골랐는지

| 안 | 형태 | 문제 |
|---|---|---|
| A | 신문 기사체(담담) | 사건 요약 느낌. 재미가 없다 |
| B | 항목 나열 | 258자로 가장 빨리 읽히지만 신문 느낌이 없다 |
| C | 헤드라인 + 본문 | A와 B의 절충. 여전히 담담하다 |
| E | 논평이 붙는 신문 | 재미있지만 **논평이 판단으로 넘어갈 위험**이 있다 |
| F | 어록 코너 | 가장 신문답고 재미있으나 **발언 인용 4개가 아이템 2종을 잡아먹는다** |

F를 버린 이유가 중요하다. 신문이 아침마다 어록을 공짜로 주면 **진술대조권과 키워드 뽑기를 왜 쓰는가**가 된다. `"저는 딸기우유 씨가 제일 수상해요"`는 진술대조 TC-1의 근거 발화 그 자체다. → 인용 상한이 필요하다(§7 미결 6)

## 3. 사망자 템플릿 — 세 경우

[게임이벤트.txt](../scenario/scenario1/게임이벤트.txt)에 **처형과 밤 살해가 다르게 기록돼 있다.**

```
[21:09:10] DEATH 딸기우유 cause=EXECUTION role=마피아     ← 역할이 붙는다
[21:09:43] DEATH 밤하늘 cause=NIGHT_KILL                ← 역할이 없다
```

→ **처형만 역할이 공개된다.**

| 경우 | 템플릿 |
|---|---|
| 밤 살해 | `■ {이름} 님, 지난 밤 유명을 달리하다` |
| 처형 | `■ {이름} 님 처형 — {역할}였다` |
| 아무도 안 죽음 | `■ 평화로운 밤이었습니다` (17-7) |

R3처럼 처형과 밤 살해가 겹치면 두 줄 다 나간다.

**역할은 반드시 서버가 넣는다.** LLM에게 "딸기우유가 마피아였다"를 주면 절대 규칙 2를 어기는 것이고, 본문에서 그 정보로 다른 사람을 추측할 위험이 생긴다.

## 4. 폴백 — 사망자 줄이 남는 이유

`17-7`의 고정 템플릿은 정확성 장치가 아니라 **LLM 호출이 실패했을 때의 폴백**이다.

```
정상   [사망자 줄 — 서버]  +  [토론 요약 — LLM]
실패   [사망자 줄 — 서버]  만
```

```
【601 조간】 제2호

■ 소금빵 님, 지난 밤 유명을 달리하다
```

이것만 나가도 **정보 손실은 없다** — 사망은 어차피 실시간 이벤트로도 나간다. 잃는 것은 재미뿐이다.

따라오는 것:

- **사망자 줄은 LLM 출력과 문장이 이어지면 안 된다.** 요약이 없어도 홀로 성립해야 한다. D안 골격은 `■` 두 줄이 독립적이라 이 조건을 만족한다
- **타임아웃을 짧게 잡을 수 있다.** 생성 가용 시간이 60초 이상이지만([§6](../../docs/AI기능-구현설계.md)) 실패해도 신문이 나가므로 오래 기다릴 이유가 없다
- 재시도 여부는 **§7 미결 3**

## 5. 조작권 (17-4·17-5, [TC-15](../scenario/scenario1/테스트-체크리스트.md))

초코비(초코비)이 R1 밤 `21:04:38`에 `NEWSPAPER_EDIT`을 썼다. R2 신문은 조작본이어야 한다.

**AI 심판·방어권 결과는 조작 대상이 못 된다.** 실시간 이벤트로 이미 전원에게 나갔으므로, 그것을 부정하면 모두가 즉시 알아챈다.

노릴 것은 **신문만 말해주는 부분, 즉 토론 요약**이다.

```
원본  초코비 님은 곧바로 "제일 수상하다"며 손가락을 들었다.

조작  딸기우유 님을 향한 시선이 모였다. 회의는 결론 없이 끝났다.
```

초코비는 R2 낮에 "저는 처음부터 딸기우유 씨를 믿었습니다"(`21:06:20`)라고 우긴다. **신문에 저 줄이 남아 있으면 바로 걸리므로 자기 이름을 지운다.**

픽스처가 여기에 맞물려 있다.

```
21:04:55  곰돌이: 근데 신문 내용이 좀 이상한데요 어제 흐름하고 안 맞아요
21:06:30  곰돌이: 방금 그 말 어제랑 완전히 다르잖아요 어제는 제일 수상하다고 했어요
```

곰돌이는 직접 들었으므로 조작을 알아챈다. **조작권이 진술대조권의 증거를 미리 지우려는 시도**가 되는 구조다.

LLM은 관여하지 않으므로 프롬프트 대상이 아니고, **기대답안에 원본/조작본 쌍으로 넣는다.**

## 6. 프롬프트 규칙 후보

진술대조에서 배운 대로 **짧게** 가고, 코드로 막을 것은 프롬프트에 넣지 않는다 ([진술대조 §2-3](진술대조.md)).

| 규칙 | 왜 |
|---|---|
| **누가 수상한지 판단하지 않는다.** 누가 누구를 의심했는지만 쓴다 | 딸기우유는 실제 마피아다. 신문이 판단하면 시민에게 정답을 준다 |
| 발언 인용은 **N개까지** (§7 미결 6) | 많으면 아이템 2종이 시들해진다 |
| 주어진 발언 밖의 사실을 쓰지 않는다 | 환각 방어 |
| 중요한 것을 앞에 배치한다 | 10초만 표시한다(17-6) |
| 500자 이내 | 17-2. 1000 → 500 수정 예정 |

서버가 하는 것 — 사망자 줄 삽입 · 500자 truncate · **밤 로그 문자열 검사**(TC-12) · 머리글(§7 미결 4).

### 실패 예시로 기대답안에 넣을 것

```
✗  가장 수상한 인물로 딸기우유 님이 떠올랐다
✗  회의를 방해하려는 의도가 읽힌다
```

톤이 세지는 것과 판단하는 것은 다르다. `"시간 낭비"라던 딸기우유 님, 하루 만에 최다 지목자로`는 사실 요약이라 괜찮다.

## 7. 미결 — 다음 세션 첫 작업

### 1. 생성 시점 — 이걸 먼저 정해야 나머지가 정해진다

[명세 17-1](../../docs/기능명세서.md)은 **낮 투표 시작**이다. R1에 대입하면 `21:03:06`인데, **어젯밤의 큰 사건 셋이 그 뒤에 일어난다.**

```
21:03:06  R1/DAY_VOTE 시작       ← 17-1대로면 여기서 생성
21:03:36  투표 3자 동률
21:04:08  AI 심판 → 초코비 지목 → 방어권 발동
21:04:42  소금빵 사망
21:04:45  R2 낮 시작 → 신문 공개   ← 유저가 읽는 시점
```

[§6](../../docs/AI기능-구현설계.md)에 생성 가용 시간이 60초 이상이라 적혀 있으므로 **밤 시작 직전으로 늦출 수 있다**(17-3보다만 앞서면 된다). §2의 예시들은 늦춘 쪽으로 썼다.

### 2. 투표·심판 결과를 신문에 넣을지

**AI 심판과 방어권은 이미 실시간 이벤트로 전원에게 나간다.** 신문이 다시 쓰면 500자 중 한 문단을 모두가 아는 것에 쓰는 셈이다.

→ 빼고 그 분량을 토론 요약에 몰아주는 편이 나아 보인다. 그러면 §2 예시의 마지막 문단이 투표 결과 정도로 짧아진다.

### 3. 폴백 시 재시도할지

안 하면 요약 없는 신문, 하면 지연이 늘어난다. 요약 없는 신문도 그럭저럭 성립하므로 재시도 없이 넘기는 것도 선택지다.

### 4. `【601 조간】 제N호` 머리글을 누가 쓸지

서버가 붙이는 것이 안전해 보인다 — 호수를 LLM이 틀릴 일이 없어진다.

### 5. STT 오류를 신문이 교정해도 되는지

로그에는 `시간 남비`·`라멘왕`·`밥하늘`·`초코피`로 깨져 있고, §2 예시에서는 교정했다. **신문은 인용이 아니라 요약이므로 교정이 자연스러운데**, 진술대조·키워드에서 세운 "원문에 없는 말을 만들지 않는다"와 방향이 다르다. 기능마다 다르게 갈 근거는 있다 — 신문은 창작이고 아이템은 증거다.

단, 인용 부분(큰따옴표 안)은 교정하면 안 될 수도 있다. 유저가 실제 발언과 대조할 수 있는 유일한 지점이기 때문이다.

### 6. 인용 상한을 몇 개로 할지

인용할 발언을 **LLM이 고르므로 하필 결정적 증거를 인용할 위험**이 있다. §2 예시는 2~3개다. 프롬프트에 상한을 명시해야 한다.

### 7. 그 다음 — 작업 순서

1. 위 6개 결정
2. 프롬프트 문안 작성 (§6 규칙 표 → 실제 문장)
3. 노트북 `# 3. 조간신문` 아래 셀 작성 — **진술대조 5셀 구조를 베낀다.** ① 컷오프 · ② 렌더 · ③ 프롬프트 · ④ 호출 · ⑤ 실행. 단 ②는 화자를 안 가리므로 번호·`by_id`가 필요 없다
4. R2·R3 두 케이스 각 3회 실행 (1회로 판단하지 않는다)
5. **TC-12 밤 로그 유출 검사를 문자열 검색으로 자동화** — 이것부터 붙인다
6. 기대답안 문서 — 정상 2건 + 폴백 1건 + 조작본 1건

모델은 `gpt-4o-mini` / `temperature 0.7~0.8` / `max_tokens` (창작이므로) → [LLM호출설정 §4](../../docs/LLM호출설정.md)
