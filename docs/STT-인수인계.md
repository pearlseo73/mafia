# STT 발화 수집 — 프론트·백엔드 인수인계

> 작성: 2026-07-31
> 대상: **프론트엔드 담당** (§1) · **백엔드(게임 로직) 담당** (§2)
> 근거·실측: [발화수집-STT.md](발화수집-STT.md) — 왜 이렇게 정했는지는 그쪽에 있다
> 참고 구현: [log_analysis/stt-test/index.html](../log_analysis/stt-test/index.html)

AI 기능 5종(조간신문 · AI 심판 · 진술대조권 · 키워드 뽑기 · 칭호 부여)은 **모두 같은 발화 로그 하나**를 입력으로 쓴다. 이 문서는 그 로그가 만들어져 Redis 에 들어가기까지의 계약이다. **AI 파트는 Redis 에 있는 것만 읽는다** — 여기까지가 프론트·백엔드 몫이다.

이 문서에 코드는 없다. 프론트 구현은 위 측정 페이지가 **동작하는 참고 구현**이고, 거기서 무엇을 바꿔야 하는지를 §1-2 에 적었다.

---

## 0. 한 장 요약 — 누가 무엇을 하는가

| | 하는 일 | 절대 하지 않는 일 |
|---|---|---|
| **프론트** | Web Speech API 로 자기 마이크만 인식 → **final 결과 텍스트만** WS 로 보낸다 | `playerId` · `phase` · `round` 를 붙이지 않는다. interim 결과를 보내지 않는다 |
| **백엔드** | 텍스트에 `speaker` · `round` · `phase` · 시각을 붙여 **키 2개 중 하나**에 넣는다. TTL 을 건다 | 발화 원문을 MySQL 에 저장하지 않는다. 밤 발화를 낮 키에 넣지 않는다 |
| **AI** | 키에서 꺼내 기능별로 걸러 LLM 에 넣는다 | 밤 키를 낮 기능에서 읽지 않는다 |

**화자 구분은 공짜다.** 각자 자기 브라우저에서 자기 마이크만 인식하므로, 오디오 하나에서 목소리를 갈라내는 문제가 없다. 대신 **브라우저가 Chrome/Edge 로 고정**된다 (Firefox 미지원).

## 1. 프론트엔드

### 1-1. 참고 구현

[log_analysis/stt-test/index.html](../log_analysis/stt-test/index.html) 의 `<script>` 블록이 그대로 참고 구현이다. Live Server 로 열어야 마이크가 열린다 (`file://` 은 안 된다).

| 볼 것 | 위치 |
|---|---|
| 인식기 생성 · 필수 설정 3줄 | `createRecognition()` |
| `resultIndex` 부터 순회 (처음부터 돌면 중복 처리된다) | `onresult` |
| **`onend` 재시작** — Chrome 은 조용하면 알아서 종료한다 | `onend` |
| 권한 거부(`not-allowed`) 와 흔한 오류(`no-speech`) 구분 | `onerror` |

### 1-2. 측정 페이지에서 바꿔야 하는 것

| 측정 페이지 | 실서비스 |
|---|---|
| final 결과를 화면 표에 쌓는다 | **WS 로 서버에 보낸다** (§2-1) |
| `confidence` 를 표에 찍고 0.8 미만을 강조한다 | **`confidence` 를 쓰지 않는다.** 아래 참조 |
| 시작·정지 버튼을 사람이 누른다 | **phase 전환에 맞춰 자동으로** 시작·정지 (밤에 시민 마이크는 꺼야 한다) |
| 자동 재시작이 체크박스다 | **항상 켠다.** 끄면 게임 중에 조용히 죽는다 |

**`confidence` 로 자체 필터링하지 말 것.** 실측에서 **틀린 것은 자신 있게 오고 맞은 것이 낮게 왔다.** 위험한 오인식은 전부 0.8 이상이었고, 0.8 미만은 짧은 대꾸와 정확히 맞은 문장 둘뿐이었다. 필터를 걸면 맞은 발화만 사라진다 → [발화수집-STT §4-5](발화수집-STT.md)

### 1-3. 필수 설정

| 설정 | 값 | 안 하면 |
|---|---|---|
| `lang` | `'ko-KR'` | 한국어를 영어로 인식한다 |
| `continuous` | `true` | 한 문장 끝나면 멈춘다 |
| `interimResults` | `true` | 화면에 "인식 중…"을 보여줄 수 없다. **단 서버로는 final 만 보낸다** |
| `onend` 재시작 | 300ms 뒤 `start()` | 조용한 구간 뒤로 발화가 통째로 유실된다 |
| `getUserMedia` | `echoCancellation: true` | §1-4 |

### 1-4. 마이크 환경 — 에코가 진술대조권을 깨뜨린다

스피커로 나오는 **남의 목소리가 내 마이크에 들어가면 그 말이 내 발화로 저장된다.** 하지 않은 말로 모순 판정을 받는 것이다. `echoCancellation` 으로 줄이되 완전히 막히지 않으므로 **헤드셋을 권장 안내**해야 한다.

| 제약 | 내용 |
|---|---|
| 브라우저 | Chrome / Edge 만. Firefox 미지원 |
| 프로토콜 | `localhost` 또는 https |
| 네트워크 | **오디오가 구글 서버로 전송된다.** 온디바이스가 아니다 → 개인정보 고지에 명시 필요 |

### 1-5. 보내는 것

```jsonc
// WS  speech.utterance   (fire-and-forget, 응답 없음)
{ "text": "저는 어제 밤에 아무것도 안 했어요",
  "startedAt": 1721980000123, "endedAt": 1721980002456 }
```

- **final 결과만.** interim 은 보내지 않는다
- `text` 500자 상한 (초과분은 서버가 절단)
- **`playerId` · `roomId` · `phase` · `round` 를 보내지 않는다.** 서버가 세션과 게임 상태에서 유도한다 → [AI-API명세 §0-1](AI-API명세.md)
- 예상 유량: 6명 × 3분 토론 → 라운드당 수십 건 (실측 픽스처는 라운드당 22~29건)

## 2. 백엔드

### 2-1. 받은 발화에 서버가 붙이는 것

클라이언트가 보내는 것은 **텍스트뿐**이고 나머지 4개는 서버가 채운다.

| 필드 | 출처 | 왜 서버인가 |
|---|---|---|
| `speaker` | WS 세션 | 클라이언트가 보내면 타인 명의 발화 위조가 된다 |
| `round` | 게임 타이머 | 서버가 이미 갖고 있다 |
| `phase` | 게임 타이머 | **§2-4.** 클라이언트가 지정하면 밤 발화를 낮으로 위장해 공개 로그에 심을 수 있다 |
| 시각 | 서버 수신 시점 | 정렬·컷오프 기준 |

**그래서 클라이언트가 조작할 수 있는 것은 텍스트뿐이다.**

`startedAt` / `endedAt` 은 **표시·진단 보조용으로만** 쓴다. 키 선택(낮/밤)을 클라이언트 시각으로 판단하면, 마피아가 자기 낮 발화를 밤 발화로 위장해 **진술대조권의 사정거리에서 빼낼 수 있다.**

### 2-2. Redis 키 2개

```
utt:{roomId}:public    낮 계열 전부
utt:{roomId}:night     밤 마피아 대화만
```

| | |
|---|---|
| 자료구조 | ZSET, `score` = 발화 시각 |
| 값 | 발화 1건 JSON (§2-3) |
| TTL | 두 키 모두 — 게임 종료 + 여유. **구체값 미결** (§4) |
| 사람별·라운드별 분리 | **하지 않는다.** 6명 × 3라운드 × 4페이즈면 키가 72개가 되고, 전체 대화를 복원할 때 72개를 시각순으로 병합해야 한다. 그 코드가 틀리면 순서가 어긋난 로그로 AI 가 판단한다 |

**키를 처음부터 갈라두는 것이 이 설계의 핵심이다.** 하나의 리스트에 `visibility` 필드를 두고 조회 때 거르는 방식은 채택하지 않았다 — 어느 기능에서 **한 번만 필터를 빠뜨리면 마피아 신원이 노출**된다. 키가 애초에 다르면 실수해도 새지 않는다 (명세 21-2).

### 2-3. 저장하는 발화 1건

```jsonc
{ "t": "21:06:20", "speaker": "초코비", "round": 2,
  "phase": "DAY_DISCUSSION", "text": "마음이 바뀐 겁니다 그게 이상한가요" }
```

필드 5개가 전부다. 실제 데이터는 [발화로그-공개-STT.jsonl](../log_analysis/scenario/scenario1/발화로그-공개-STT.jsonl) 79건이 그대로 이 모양이니 그것을 계약 샘플로 보면 된다.

**규모는 작다** — 한 판 전체가 공개 79건 1,967자 · 밤 9건 197자 · JSONL 로 12KB다. 전체를 꺼내 메모리에서 걸러도 된다.

### 2-4. `phase` — 7종, 그리고 어느 키에 넣을지

| `phase` | 키 |
|---|---|
| `DAY_START` · `DAY_DISCUSSION` · `DAY_VOTE` · `AI_JUDGMENT` · `FINAL_DEFENSE` · `RESULT` | `:public` |
| `NIGHT` + 발화자가 **마피아** | `:night` |
| `NIGHT` + 발화자가 **시민** | **버린다** (명세 21-2 상 애초에 전송되지 않아야 하는 발화) |

**`phase` 는 "있으면 좋은 것"이 아니라 없으면 진술대조권이 깨지는 것이다.**

투표 단계의 "저는 딸기우유 씨입니다"는 투표 선언인데, `phase` 가 없으면 LLM 이 **"나는 딸기우유다"라는 정체 주장으로 읽고** 다른 발언과 모순이라고 답한다. 모순이 없는 인물을 지목했을 때 **3회 중 3회 재현**됐고, `phase` 를 넣으면 **3회 중 0회**로 사라졌다. 주어 생략이 흔한 한국어에서 문장만으로는 두 해석을 가릴 수 없다 — **LLM 이 추측할 문제가 아니라 서버가 알려줄 사실이다** → [진술대조 §2-3](../log_analysis/prompts/진술대조.md)

저장 시점에 붙이는 것이 정석이다. 나중에 투표 시작·종료 시각으로 역산하는 우회로가 있지만 그건 우회로다.

### 2-5. 밤↔낮 경계 — 여유를 둬야 한다

**STT 는 말이 끝난 뒤에 결과를 준다.** 전환 직전에 시작한 발화가 직후에 도착하면 phase 가 하나 밀린다.

- 낮 안에서(토론 → 투표) 몇 초 밀리는 것은 문제가 안 된다
- **밤 발화가 낮 키에 들어가면 마피아가 노출된다.** 밤 → 낮 경계에는 버퍼를 둔다
- 버퍼 초는 미결 (§4). 방향은 **의심스러우면 밤으로 취급**하는 쪽이다 — 낮 로그에서 한 건 빠지는 손해가 신원 노출보다 작다

### 2-6. 영구 저장 금지

**발화 원문을 MySQL 에 넣지 않는다.** 음성에서 나온 텍스트는 개인정보이고 게임이 끝나면 필요가 없다. MySQL 에 넣으면 지우는 코드를 따로 만들어야 하고, 안 지우면 계속 쌓인다. **MySQL 에는 승패·통계·칭호만 남긴다.**

## 3. AI 가 이 로그를 어떻게 읽는가 (참고)

백엔드가 구현할 것은 아니지만, **필드가 왜 다 필요한지**가 여기서 보인다.

| 기능 | 화자 | 시점 | `phase` |
|---|---|---|---|
| 🔍 진술대조권 | 지목 대상만 | 아이템 사용 시각 이전 | `NIGHT` 제외 |
| 🏷️ 키워드 뽑기 | 지목 대상만 | 아이템 사용 시각 이전 | `NIGHT` 제외 |
| 📰 조간신문 | 전원 | 직전 라운드의 낮 | **4종만** (`DAY_DISCUSSION`·`DAY_VOTE`·`AI_JUDGMENT`·`FINAL_DEFENSE`) |
| ⚖️ AI 심판 | 전원 (사망자 포함) | 심판 발동 시각 이전 | `NIGHT` 제외 |
| 🏆 칭호 부여 | 전원 | 게임 전체 | `NIGHT` 제외 |

- **낮 기능은 `:night` 키를 아예 읽지 않는다.** 조회 함수를 `getPublicUtterances(roomId)` 하나로 두고, 밤 키 접근 경로는 결산 코드에만 존재하게 한다
- **칭호도 밤 대화를 읽지 않는다** (2026-07-31 확정). 밤 구간에서 쓰는 것은 서버 이벤트(사망 라운드·원인)뿐이다
- 컷오프는 전부 **코드가 자른다.** 프롬프트에 "몇 시까지"를 글로 적으면 모델이 안 지킨다

### 3-1. AI 파트가 게임 로직에 별도로 요청하는 것

발화 로그와 별개로 필요한 것들이다. 상세는 [AI-API명세 §5](AI-API명세.md).

| | 용도 |
|---|---|
| phase 전환 훅 (서버 내부 이벤트) | 신문·심판·칭호 생성 트리거. **방 생성 시 LLM 워밍업** 포함 — 첫 호출만 4~7초라 R1 신문이 폴백으로 떨어진다 |
| 생존자·역할 목록 | 심판 대상 검증 |
| 라운드별 투표 내역 · 아이템 사용 이력 | 칭호 지표 |
| 사망 이벤트 (라운드·원인) | 신문 사망자 줄, 칭호 지표 |
| WS 개별 전송 (`user destination` 등) | 아이템 결과는 **본인만**, 신문 미리보기는 **조작권 소지자만** 받는다 |

## 4. 아직 안 정한 것 — 담당자와 함께 정해야 한다

| 항목 | 선택지 | 정해야 하는 쪽 |
|---|---|---|
| **TTL 구체값** | 게임 종료 + 몇 분? 결산·재접속 복구가 끝나는 시점보다 넉넉해야 한다 | 백엔드 |
| **시각 필드 형식** | `t` 를 `HH:MM:SS` 문자열로 둘지, epoch ms 로 저장하고 렌더 때 변환할지. **자정을 넘기면 문자열 비교가 깨진다** — epoch 권장 | 백엔드 + AI |
| **밤→낮 경계 버퍼** | 몇 초를 밤으로 취급할지 | 백엔드 + 게임 기획 |
| **`text` 500자 절단** | 절단인지 폐기인지. STT 는 문장을 합쳐서 오므로 실제로 길어질 수 있다 | 백엔드 |
| **phase 전환 시 마이크 제어** | 밤에 시민 마이크를 프론트가 끄는지, 서버가 버리는지, 둘 다인지 (**둘 다 권장**) | 프론트 + 백엔드 |
| **닉네임 제약** | STT 는 사전에 없는 닉네임을 못 맞춘다. 한글·길이 제한을 걸지 | 게임 기획 |

## 5. 수용 기준 — 이게 되면 AI 파트가 붙는다

**프론트**

- [ ] Chrome 에서 3분 토론 동안 인식이 끊기지 않는다 (`onend` 재시작 동작)
- [ ] final 결과만 전송된다 (interim 이 서버에 도착하지 않는다)
- [ ] 페이로드에 `playerId` · `phase` · `round` 가 없다
- [ ] 밤에 시민 클라이언트의 인식기가 정지한다
- [ ] 마이크 권한 거부 시 사용자에게 안내가 나간다

**백엔드**

- [ ] `utt:{roomId}:public` 에 5개 필드가 다 채워져 시각순으로 쌓인다
- [ ] **`phase` 가 7종 중 하나로 정확히 붙는다** — 특히 `DAY_VOTE` 와 `FINAL_DEFENSE` 구분
- [ ] 밤 마피아 발화가 `:night` 로만 간다. **`:public` 을 전량 덤프해 밤 발화 문구를 문자열로 검색했을 때 0건이다**
- [ ] 밤 시민 발화가 어느 키에도 남지 않는다
- [ ] 두 키에 TTL 이 걸려 있고 게임 종료 후 만료된다
- [ ] MySQL 어느 테이블에도 발화 원문이 없다
