# 00. 코드 스타일 — 어떻게 호출하는가

> 원본: `reference/spring-ai-tool_완성본` (강사님 예제. 남의 코드라 git 에 커밋하지 않는다)
> 결정 근거: [docs/LLM호출설정.md](참고/LLM호출설정.md) · [docs/개발환경.md](참고/개발환경.md)

강사님 예제의 호출 방식을 그대로 따른다. **`.entity()` 를 쓰지 않고 `.content()` 로 받는다.**

---

## 1. 의존성

| | reference 완성본 | ai-lab |
|---|---|---|
| Spring Boot | 4.0.6 | 4.1 |
| Java | 25 | 25 |
| Spring AI | 2.0.0-RC1 | 2.0 |
| 스타터 | `spring-ai-starter-model-openai` | 같음 |
| 빌드 | Maven | Gradle |

**팀 레포의 버전에 맞춘다.** 아래 두 가지만 버전에 걸린다.

- **`.options()` 가 `Builder` 를 받는다 (Spring AI 2.0).** 1.x 는 완성된 `ChatOptions` 를 받으므로 예제에 `.build()` 가 붙어 있는데, 2.0 에서 그대로 쓰면 컴파일되지 않는다
- 프로퍼티 경로가 1.x ↔ 2.0 에서 다르다 → [LLM호출설정 §2](참고/LLM호출설정.md)

---

## 2. `ChatClient` 빈 하나

```java
@Configuration
public class AiConfig {
    @Bean
    public ChatClient chatClient(ChatClient.Builder builder) {
        return builder.build();
    }
}
```

스타터가 자동 등록하는 것은 `Builder` 다. 그것을 **한 번만** `build()` 해서 `ChatClient` 빈으로 두고, 쓰는 쪽은 `ChatClient` 를 주입받는다. **호출마다 `build()` 하지 않는다.**

기능마다 모델·파라미터가 달라도 **빈을 여러 개 만들지 않는다.** 호출 시 `.options()` 로 덮어쓴다 (§5).

---

## 3. 프로퍼티 — GMS 경유

reference 완성본에서 GMS 부분만 가져온 것이다.

```properties
# .env 자동 로드 (없으면 무시 / OS 환경변수가 우선)
spring.config.import=optional:file:.env[.properties]

gms.base-url=${GMS_BASE:https://gms.ssafy.io/gmsapi}
gms.key=${GMS_KEY:}

# base-url 에 /v1 필수 — SDK 가 /chat/completions 만 붙인다. 빼면 GMS 404
spring.ai.openai.base-url=${gms.base-url}/api.openai.com/v1
spring.ai.openai.api-key=${gms.key}
spring.ai.openai.chat.model=gpt-4o-mini
```

### 🔴 전역에 토큰 상한을 두지 않는다

`spring.ai.openai.chat.max-tokens` 를 두면 **`gpt-5.x` 계열 호출이 전부 깨진다.** 호출에서 `.options()` 로 `model` 만 덮어써도 기본 옵션의 `max_tokens` 가 병합돼 함께 나가고, `gpt-5.x` 는 그것을 받으면 **HTTP 400** 이다. 런타임 옵션은 필드 단위 덮어쓰기라 값을 비워 지울 수 없다.

**모델과 토큰 상한은 항상 호출 쪽 `.options()` 에서 짝으로 준다.**

`.env` 에 `GMS_KEY` · `GMS_BASE` 를 두고 **커밋하지 않는다.**

## 4. 호출 패턴

```java
String raw = chatClient.prompt()
        .system(systemText)                 // 문자열 그대로. 템플릿 렌더 없음 (§6)
        .user(u -> u.text(USER_RES, StandardCharsets.UTF_8)
                    .param("log", renderedLog)
                    .param("target", target))
        .options(OpenAiChatOptions.builder()
                    .model("gpt-4o-mini").maxTokens(512))   // .build() 안 붙인다
        .call()
        .content();
```

- **`.content()` 로 받는다.** 파싱은 직접 하고 실패는 폴백으로 흡수한다
- `.text(resource, StandardCharsets.UTF_8)` — **인자 2개짜리를 쓴다.** 1개짜리는 플랫폼 기본 인코딩을 타서 한글 프롬프트가 깨질 수 있다
- 리소스는 `static final` 상수로 둔다 (`new ClassPathResource("prompts/...")`). `@Value` 필드 주입과 `@RequiredArgsConstructor` 를 섞지 않아도 된다
- 서비스는 Lombok `@RequiredArgsConstructor` 로 생성자 주입 → [개발환경 §4-1](참고/개발환경.md)

### `.entity()` 를 쓰지 않는 이유

`.entity()` 는 **Spring AI 가 스키마 지시문을 프롬프트 뒤에 자동으로 덧붙인다.** 그러면 노트북과 Spring 이 서로 다른 프롬프트를 보내게 되고, 노트북에서 잰 성적이 보장되지 않는다. 강사님 예제도 `.content()` 다.

출력 형식 지시는 **프롬프트에 직접 적혀 있다** — `prompts/*-system.st` 안의 JSON 예시가 그것이다.

## 5. 기능별 모델·파라미터 — 노트북 실측값 그대로

| 기능 | 모델 | temperature | 토큰 상한 | 파라미터 이름 |
|---|---|---|---|---|
| 🔍 진술대조권 | `gpt-5.4-mini` | 0 | 2048 | **`maxCompletionTokens`** |
| 🏷️ 키워드 뽑기 | `gpt-4o-mini` | 0 | 512 | `maxTokens` |
| 📰 조간신문 | `gpt-4o-mini` | **0.8** | **300** | `maxTokens` |
| ⚖️ AI 심판 | `gpt-5.4-mini` | **0.7** | 2048 | **`maxCompletionTokens`** |
| 🏆 칭호 부여 | `gpt-4o-mini` | **0.9** | 1500 | `maxTokens` |

### 🔴 모델을 바꾸면 파라미터 이름도 바꿔야 한다

**`gpt-5.x` 에 `max_tokens` 를 주면 HTTP 400 이다.**

```
Unsupported parameter: 'max_tokens' is not supported with this model.
Use 'max_completion_tokens' instead.
```

`gpt-4o-mini` 는 `maxTokens`, `gpt-5.4-mini` 는 `maxCompletionTokens`. 폴백으로 모델을 바꿀 때 여기서 걸린다.

### 알아둘 것

- **`temperature=0` 이어도 출력이 매번 다르다** (실측). GMS 가 무시하는지 모델 특성인지 미확인. **한 번 돌려서 판단하지 않는다**
- **조간신문의 `maxTokens=300` 이 글자수의 유일한 실효 상한이다.** 프롬프트에 "500자 이내"를 적어도 안 지켜졌다. 1토큰 ≈ 1.5자라 300 이면 450자쯤에서 막힌다
- `gpt-5.4-mini` 의 토큰 상한을 넉넉히 두는 것은 **과금이 아니라 잘림 방지**용이다. 추론 토큰이 상한을 같이 먹는다 (실측에서는 `reasoning_tokens=0` 이었다)
- **첫 호출만 4~7초** 걸린다 (커넥션·SDK 초기화). **방 생성 시점에 워밍업 호출을 한 번 태운다** — 조간신문 생성 창이 R1 4초라 없으면 첫 신문이 폴백으로 떨어진다

## 6. 🔴 프롬프트 `.st` — SYSTEM 은 렌더하면 깨진다

프롬프트는 `src/main/resources/prompts/*.st` 로 뺀다. 파일명은 `{기능}-{system|user}.st`.

강사님 예제는 시스템 프롬프트를 클래스 안 텍스트 블록에 두는데, **우리는 파일로 뺀다.** 이유는 수정 빈도다 — 프롬프트 자체가 산출물이고 반복 튜닝이 작업의 본체라, 한 글자 고칠 때마다 재컴파일하면 그 비용이 계속 누적된다.

### 문제

`.st` 는 StringTemplate 파일이고 **`{}` 가 변수 구분자**다. 그런데 SYSTEM 프롬프트에는 **출력 형식 지시로 JSON 예시가 들어 있다.**

```
statement-compare-system.st   {"hasFindings": true, "ids": ["u2","u5"], ...}   ← 중괄호 2쌍
keyword-extract-system.st     {"keywords": [{"keyword": ...}]}                  ← 2쌍
title-award-system.st         {"titles": [{"nickname": ...}]}                    ← 2쌍
ai-judge-system.st            처형 대상은 {닉네임}입니다.                        ← 1쌍
newspaper-system.st           (없음)                                             ← 유일하게 안전
```

**이걸 템플릿으로 렌더하면 파싱 오류가 나거나 JSON 예시가 사라진다.** 예시가 사라지면 모델이 JSON 을 내놓지 않는다 — 조용히 품질만 떨어진다.

### 해결 — SYSTEM 은 문자열로 읽고, USER 만 렌더한다

```java
// SYSTEM — 렌더 금지. 파일 내용을 문자열로 읽어 그대로 넘긴다
private static final Resource SYS = new ClassPathResource("prompts/statement-compare-system.st");
String systemText = SYS.getContentAsString(StandardCharsets.UTF_8);
...
.system(systemText)     // String 오버로드는 템플릿을 거치지 않는다

// USER — 이쪽만 템플릿. 중괄호가 전부 변수라 안전하다
.user(u -> u.text(USER_RES, StandardCharsets.UTF_8).param("log", ...).param("target", ...))
```

**노트북도 정확히 같은 구조다** — 각 프롬프트 셀에 `SYSTEM 에 .format() 을 쓰지 않는다. 값을 끼우는 것은 USER 쪽뿐이다` 라고 적혀 있다. 이식할 때 이 경계를 그대로 유지한다.

USER 파일 5개의 중괄호는 **전부 실제 변수**다 (확인함). 그대로 `.param()` 이름이 된다.

| USER 파일 | 변수 |
|---|---|
| `statement-compare-user.st` | `log` · `target` |
| `keyword-extract-user.st` | `target` · `now` · `utterances` |
| `newspaper-user.st` | `log` |
| `ai-judge-user.st` | `alive_players` · `player_statistics` · `public_day_utterances` |
| `title-award-user.st` | `winner` · `players` · `votes` · `public_day_utterances` |

> SYSTEM 도 템플릿으로 넣고 싶어지면 렌더러의 구분자를 바꾸는 방법이 있다 (`StTemplateRenderer` 의 `startDelimiterToken`). **권하지 않는다** — 프롬프트 문안을 건드리게 되고, 노트북과 다른 문자열을 보내는 순간 실측 성적이 무의미해진다.

## 7. 출력 파싱 — 공통

모델이 ```json 으로 감싸는 경우가 있어 벗겨낸다. 노트북 `strip_fence` 와 같은 규칙이다.

```
정규식:  ^```(?:json)?\s*   그리고   \s*```$   를 제거
```

**파싱 실패도 결과로 본다.** 예외를 던지지 않고 "실패"를 돌려 폴백 판단에 쓴다. 실측된 실패 원인은 하나였다 — **칭호의 `reason` 안에서 발언을 큰따옴표로 감싸 JSON 문자열이 끊겼다.**

## 8. 함정 모음

| 함정 | 결과 |
|---|---|
| `base-url` 에서 `/v1` 을 빼먹음 | GMS 404 |
| 전역 프로퍼티에 `max-tokens` | `gpt-5.x` 호출 전부 HTTP 400 |
| `gpt-5.x` 에 `maxTokens` | HTTP 400 |
| `.options(...build())` (Spring AI 2.0) | 컴파일 오류 |
| `.text(resource)` 1인자 | 한글 프롬프트 인코딩 깨짐 |
| SYSTEM `.st` 를 템플릿으로 렌더 | JSON 예시 소실 → 모델이 JSON 을 안 냄 |
| `.entity()` 사용 | 프롬프트에 스키마 지시문이 자동 추가 → 노트북과 다른 프롬프트 |
| 워밍업 없음 | 첫 호출 4~7초 → R1 조간신문 폴백 |
| `GET /models` 로 모델 탐색 | GMS 미지원. 확인된 모델은 `gpt-4o-mini` · `gpt-5.4-mini` 둘뿐 |
