## 0. 진술대조권과 무엇이 다른가

입력 소스(지목 대상의 발화)만 같고 나머지가 다르다. [§7-1](../../docs/AI기능-구현설계.md)

| | 진술대조권 | **키워드 뽑기** |
|---|---|---|
| 목적 | 발언 간 모순 탐지 (**추론**) | 무슨 말을 했는지 (**추출**) |
| 로그 범위 | 전체 라운드 | **현재 라운드만** ← 핵심 차이 |
| 역할 제한 | 시민만 | **전원** (마피아도 사용) |
| 모델 | `gpt-5.4-mini` | **`gpt-4o-mini`** — 토론 중 호출이라 가장 싸고 빠른 쪽 |
| temperature | — | **0** (창작이 아니라 추출) |

**현재 라운드로 제한하는 이유:** 전체 라운드를 보면 진술대조권과 산출물이 사실상 겹쳐서 아이템 두 개를 둘 이유가 없어진다. 라운드 간 변화는 진술대조권의 몫이다.

## 1. 입력을 만드는 규칙

| 항목 | 값 |
|---|---|
| 로그 소스 | `utt:{roomId}:public` **만** |
| 라운드 범위 | **현재 라운드만** |
| 화자 범위 | 지목 대상 1명의 발화만 |
| 시간 범위 | **아이템 사용 시각까지** |
| 역할 정보 | 넣지 않는다 |

시간 범위가 특히 중요하다. 아이템은 토론 중에 쓰이므로 그 라운드의 `DAY_START` + `DAY_DISCUSSION` 중 **사용 시각 이전** 발화만 존재한다. 이후 발화는 그 시점에 아직 없었다.

### 발화 임계값 — LLM을 호출하지 않는 조건

진술대조권과 같은 기준을 쓴다.

```
대상의 현재 라운드 발화가 3건 미만  또는  총 글자수 40자 미만  →  LLM 호출 없이 즉시 응답
```

**현재 라운드만 보기 때문에 진술대조권보다 임계값에 훨씬 자주 걸린다.** R1 토론 초반에는 대부분이 미달이다.

## 2. 출력 계약

```jsonc
{
  "hasFindings": true,
  "keywords": ["시간 낭비", "느낌", "억울", "시민"]   // 3~5개
}
```

발화가 부족할 때:

```jsonc
{ "hasFindings": false, "noFindingReason": "INSUFFICIENT", "keywords": [] }
```

`noFindingReason`: `INSUFFICIENT` (발화 부족). 화면 문구는 서버가 이 enum으로 고른다.

> 진술대조권과 달리 `NO_CONTRADICTION`에 대응하는 값이 없다. 발화가 임계값을 넘으면 뽑을 키워드는 반드시 있다.

**서버가 감싸는 부분** — `requestId`, `itemCode`, `targetPlayerId`. [AI-API명세 §2-5](../../docs/AI-API명세.md)의 형태와 일치한다.

### 환각 방어 — 원문 부분 문자열 검사

진술대조권은 발화 번호로 인용 환각을 막았다. 키워드는 성질이 달라서 **서버가 부분 문자열 검사로** 막는다.

```
각 키워드가 입력 발화 안에 실제로 등장하는 연속된 문자열인지 검사 → 아니면 버린다
비교 시 공백을 제거하고 맞춘다 ("시간낭비" ↔ "시간 낭비")
```

조사·어미를 떼는 것은 허용된다 — `억울하면` → `억울`은 부분 문자열이므로 통과한다. 반대로 로그에 없는 상위 개념어(`비협조`, `방어적`)는 통과하지 못한다.

**상위 개념어를 금지하는 이유:** 그것은 추출이 아니라 LLM의 해석이다. 해석이 섞이면 시민이 "AI가 그 사람을 비협조적이라고 판단했다"로 받아들이는데, 실제로는 아이템이 그런 판정을 하는 물건이 아니다.

## 3. 프롬프트

### System

```
당신은 마피아 게임의 발언 기록에서 특징적인 표현을 뽑아내는 분석관이다.
한 플레이어가 이번 라운드에 한 말을 받아서, 그 사람의 발언을 대표하는 표현을 골라낸다.

규칙:
1. 주어진 발언에 실제로 등장하는 표현만 고른다. 요약하거나 다른 말로 바꾸지 않는다.
   조사나 어미는 떼도 된다. 없는 단어를 만들어내면 안 된다.
2. 3개에서 5개를 고른다. 각 표현은 10자 이내로 짧게.
3. 그 사람의 태도나 입장이 드러나는 표현을 우선한다.
   누구나 쓰는 말("그러니까", "저는", "네")은 고르지 않는다.
4. 마피아인지 시민인지 추측하지 않는다. 판단하지 말고 뽑아내기만 한다.
5. 결과는 지정된 JSON 형식으로만 답한다.
```

규칙 1과 3이 이 프롬프트의 전부다. 1이 없으면 없는 단어를 만들고, 3이 없으면 의미 없는 조사·감탄사가 올라온다.

### User

```
분석 대상: {targetName}
라운드: {round}

이번 라운드 발언:
{utterances}
```

`{utterances}` 렌더링 — **번호를 매기지 않는다.** 진술대조권은 번호로 인용을 지목해야 했지만, 키워드는 번호가 필요 없다.

```
저는 그런 거 시간 낭비라고 생각해요 그냥 느낌으로 가야죠
아니 그러면 삼분 동안 뭘 어떻게 하겠다는 거예요 다들 시민이라고 할 거잖아요
...
```

## 4. Spring AI로 옮길 때

- 출력 형식 지시는 `BeanOutputConverter`가 붙이므로 System 규칙 5번은 지워도 된다 → [LLM호출설정 §7](../../docs/LLM호출설정.md)

- temperature 0
