## 2. 발화 조회 — 여기가 Redis 로 바뀐다

노트북 0-2 는 JSONL 파일을 읽는다. **실서비스에서 이 함수 하나만 Redis 조회로 바뀐다.** 나머지 로직은 그대로다.

```
utt:{roomId}:public    낮 계열 전부      ← 낮 기능 5종이 읽는 유일한 키
utt:{roomId}:night     밤 마피아 대화만   ← 프롬프트 입력으로 쓰지 않는다
```

발화 한 건 (필드 5개)

```jsonc
{ "t": "21:06:20", "speaker": "초코비", "round": 2,
  "phase": "DAY_DISCUSSION", "text": "마음이 바뀐 겁니다 그게 이상한가요" }
```

계약과 저장 규칙은 [STT인수인계/back/](참고/발화수집-STT.md) 에 정리돼 있다.

### 조회 함수를 하나로 둔다

```
getPublicUtterances(roomId)   ← 낮 기능 5종이 쓰는 유일한 통로
```

**밤 키에 접근하는 경로를 만들지 않는다.** 칭호도 밤 대화를 읽지 않는다 (2026-07-31 확정). 밤 로그 경로가 존재하는 유일한 곳은 **조간신문의 유출 검사**이고, 그건 출력 검사용이라 프롬프트 입력에 닿지 않는다.

### 로드 지점에서 한 번 끊는다

노트북 `load_utterances` 는 로드 직후에 이걸 확인한다.

```
모든 발화의 phase != NIGHT 인지 assert — 아니면 즉시 실패
```

**기능마다 `phase != NIGHT` 필터를 다시 두지 않아도 되게 여기서 끊는다.** 부탁이 아니라 구조로 막는 자리다 (절대 규칙 1).

### 픽스처 로더는 `src/test` 에만

`main` 에 두면 실서비스 코드가 파일에서 발화 로그를 읽는 경로가 생긴다. 실제로는 Redis 에서 와야 한다. 테스트용 JSONL 은 [fixture/](fixture/) 에 있다.

## 3. 컷오프 — `t < now`, `now` 자체는 제외

```
before(utterances, t)  →  t 이전 발화만. t 자체는 제외 (< 이고 <= 가 아니다)
```

### 🔴 프롬프트에 "몇 시까지"를 글로 적으면 모델이 안 지킨다

실측 — 프롬프트에 `21:11:05 까지` 라고 적었더니 모델이 `21:11:20` 을 인용했다. **그 발화가 하필 진술대조 결과를 읽어주는 대사여서, 모순을 찾은 게 아니라 답을 읽은 상태가 됐다.**

### `now` 자체를 빼는 것도 의도다

컷오프 시각의 발화는 기능마다 정답을 흘린다.

| 기능 | 컷오프 시각의 발화가 |
|---|---|
| 진술대조권 · 키워드 뽑기 | 아이템 사용 발화 — **지목 대상을 먼저 알려준다** (`21:11:05` = "초코비 씨 진술 대조해볼게요") |
| AI 심판 | 심판 발동 시각의 발화 — **심판 결과에 대한 반응**이다 |

**컷오프가 동작하는지 확인하는 방법** — 진술대조에서 `21:11:20`(결과를 읽어주는 대사)이 입력에서 빠졌는지 본다.

### 지금은 노트북대로 문자열 비교로 간다

`t` 가 `"21:11:05"` 문자열이므로 문자열 비교로 컷오프한다. `HH:MM:SS` 제로패딩이면 사전순 == 시간순이라 그대로 돌아간다.

**자정을 넘기는 판에서만 깨진다.** 지금 고치지 않고 [보류 항목](#보류-항목--stt-구현이-끝난-뒤-확인할-것)으로 뒀다 — 아래 참조.

## 보류 항목 — STT 구현이 끝난 뒤 확인할 것

> **지금 손대지 않는다.** 프론트·백엔드에 넘긴 인수인계를 바꾸지 않기로 했고(2026-07-31), **계약을 바꾸지 않고 나중에 AI 쪽만 고칠 수 있는 문제**라서다. 백/프론트의 STT 발화 수집 구현이 끝난 **뒤에** 확인한다.

### 무엇이 문제인가

발화 레코드의 `t` 는 `"21:06:20"` — **시:분:초 문자열이고 날짜가 없다.** 컷오프를 문자열 비교로 하면 자정을 넘길 때 순서가 뒤집힌다.

```
"23:52:10" < "00:07:00"   →  거짓     ← 자정 이전 발화가 "더 나중" 으로 판정된다
```

게임이 23:50 시작 → 00:10 종료이고 누가 00:07 에 진술대조권을 쓰면, **23시대 발화가 전부 탈락하고 00시대 몇 건만 남는다.** 임계값(3건·40자)에 걸려 `INSUFFICIENT` 가 되고 유저에게는 **"발언이 부족합니다"** 로 보인다.

고약한 점은 **로그상 컷오프가 정상 동작한 것처럼 보인다**는 것이다. 필터가 제대로 돌았고 결과가 비어 있을 뿐이라, 원인을 찾으려면 자정을 의심해야 한다.

| 기능 | 영향 |
|---|---|
| 🔍 진술대조 · 🏷️ 키워드 | 컷오프가 깨진다 |
| ⚖️ AI 심판 | 컷오프 + 통계 분모까지 틀린다 |
| 📰 조간신문 · 🏆 칭호 | 라운드 필터라서 영향이 작다 |

**발생 조건은 게임 한 판(15~20분)이 자정을 걸치는 것**이다. 낮 시연은 무관하고 밤에 개발·테스트할 때만 걸린다. 그래서 급하지 않다.

### 왜 지금 안 고치는가

**계약을 바꿀 필요가 없을 가능성이 높다.** 발화는 Redis **ZSET** 에 들어가고, ZSET 은 `score`(숫자)로 정렬한다. 인수인계에 `score = 발화 시각`이라고 적혀 있으므로 백엔드가 자연스럽게 구현하면 `System.currentTimeMillis()` → **epoch** 가 들어간다. **epoch 는 날짜를 포함한 단조 증가 숫자라 자정 문제가 없다.**

그러면 레코드에 필드를 추가하지 않고 **AI 쪽 조회만 고치면 끝난다.**

```
(a) ZRANGEBYSCORE key -inf (cutoffEpoch    ← Redis 가 범위로 잘라준다. 필터 코드가 사라진다
(b) ZRANGE ... WITHSCORES                  ← score 를 함께 받아 그 숫자로 비교한다
```

`t` 는 프롬프트 렌더용으로 그대로 쓴다. 프롬프트에 사람이 읽는 시각이 들어가야 하는 이유는 모델이 발언 사이의 간격을 그것으로 파악하기 때문이다(`[R2 투표 21:08:10]`). **그래서 프롬프트도 [렌더 스냅샷](렌더스냅샷/)도 안 바뀐다.**

### 확인할 것 — 딱 하나

**백엔드가 ZSET `score` 에 실제로 무엇을 넣었는지.** STT 구현이 끝난 뒤 물어본다.

| `score` 값 | 판정 |
|---|---|
| epoch 밀리초 (`1721980000123`) | ✅ 그대로 전환 가능 |
| epoch 초 (`1721980000`) | ✅ 가능. 자정 문제 해결됨 |
| `210620` 처럼 시각을 숫자로 바꾼 것 | ❌ 안 된다. 그때 `ts` 필드 추가를 요청한다 |

첫째나 둘째일 가능성이 높다.

### 전환할 때 손대는 곳

컷오프 3곳 — 진술대조 · 키워드 · AI 심판. **렌더는 건드리지 않는다.**

> **밀리초까지 요구하지 않는다.** 초 단위여도 진술대조권은 문제없다 — **입력이 한 사람의 발화뿐이고, 같은 사람이 같은 초에 두 개의 final STT 결과를 낼 일이 없다.** (STT 는 오히려 발화를 합쳐서 온다 — 실측 9건→8건) 전원 발화를 쓰는 조간신문·심판·칭호에서 서로 다른 사람이 같은 초에 들어올 수는 있지만, 인접 두 발화 순서가 뒤집혀도 기사 내용이나 리듬 판정을 바꿀 정도가 아니다.

## 4. 페이즈 라벨 — 5기능 공통 상수

프롬프트에 넣는 한글 라벨이다. `phase` 원본값이 아니라 이 라벨을 렌더한다.

| `phase` | 라벨 |
|---|---|
| `DAY_START` | 시작 |
| `DAY_DISCUSSION` | 토론 |
| `DAY_VOTE` | 투표 |
| `AI_JUDGMENT` | 심판 |
| `FINAL_DEFENSE` | 최후변론 |
| `RESULT` | 결과 |

`NIGHT` 은 라벨이 없다 — 프롬프트에 들어갈 일이 없어야 정상이다. 매핑에 없는 값이 오면 **원본 문자열을 그대로 쓴다** (노트북 `PHASE_KO.get(phase, phase)`).

`DAY_START` 라벨을 "시작"으로 둔 것은 **진술대조 실측값을 유지하려는 것**이다 — 라면왕의 `DAY_START` 발화 3건이 TC-5 입력에 들어간다. 라벨을 바꾸면 그 케이스의 실측이 무의미해진다.

## 5. 게임 상태 조회 — 노트북 0-3

노트북은 [fixture/게임이벤트.txt](fixture/게임이벤트.txt) 를 파싱한다. **실서비스에서는 게임 로직 파트의 조회 인터페이스로 바뀐다** → [docs/AI-API명세 §5-2](참고/AI-API명세.md).

```
[시각] 본문   형식의 줄을 (t, round, phase, body) 로 흘린다
round·phase 는 직전 PHASE 줄에서 물고 온다 — DEATH·ITEM_USE 줄에는 라운드가 없다
PHASE 줄 자신도 흘린다 — AI 심판은 그 줄의 시각이 컷오프다
```

### 🔴 줄 순회까지만 공통이다. 필드 추출은 기능별로 둔다

**무엇을 읽지 않는가가 기능마다 다르기 때문이다.**

| 기능 | `ROLE` 줄 | 읽는 것 |
|---|---|---|
| 📰 조간신문 | ❌ 안 읽는다 | 처형자 · 처형 사유 · 밤 사망자 |
| ⚖️ AI 심판 | ❌ 안 읽는다 | 심판 발동 시각 · 그 시점 생존자 |
| 🏆 칭호 부여 | ✅ **읽는다** | 역할 · 사망(라운드·원인·phase) · 승리 진영 · 생존자 |

**공통 파서가 `roles` 를 돌려주면 실수로 쓰기 쉬워지고, 그러면 절대 규칙 2 가 무너진다.** `ROLE` 한 줄에 전원의 역할이 들어 있다.

칭호가 예외인 이유는 **게임 종료 = 역할 공개 시점**이라서다.

## 6. 사실은 서버가 계산하고 LLM 은 문장만 쓴다

강사님 예제의 `/plan-chat` 패턴(**계획 → 서버가 Tool 실행 → LLM 은 정리만**)이 우리 다섯 기능 전부의 구조다.

| 기능 | 서버가 계산 | LLM 이 쓰는 것 |
|---|---|---|
| 🔍 진술대조권 | 컷오프 · 대상 필터 · 발화 번호 · 임계값 · 번호 검증 | 짝 하나 + `reason` 한 문장 |
| 🏷️ 키워드 뽑기 | 같음 | 키워드 5개 + `evidence` |
| 📰 조간신문 | 페이즈 화이트리스트 · 결과 한 줄 · **머리글 · 사망자 줄 · 역할 공개** | 본문만 |
| ⚖️ AI 심판 | **통계 6종** · 생존자 목록 · 후보 검증 | 판결문 |
| 🏆 칭호 부여 | 승패 · 사망 원인 3종 분류 · 계약 검증 | 칭호명 · 시상평 · 근거 |

**서버가 아는 사실을 안 주면 모델이 추측하고, 추측은 과제 방향으로 기운다.** 조간신문에서 득표를 안 줬더니 최저 득표자를 "위기 맞아"로 헤드라인에 올렸다.

반대로 **낮 대화로 알 수 있는 것을 중복해서 주지 않는다** (칭호). 같은 사실을 두 번 주면 모델이 어느 쪽을 근거로 삼았는지 알 수 없다.

## 7. 폴백 — 기능마다 다르다

| 기능 | 실패했을 때 |
|---|---|
| 🔍 진술대조권 | 임계값 미달이면 **호출 자체를 안 한다** (`INSUFFICIENT`). 파싱 실패는 폴백 |
| 🏷️ 키워드 뽑기 | 파싱 실패 → 폴백. 임계값 미구현 (붙일 것) |
| 📰 조간신문 | **사망자 줄만 나가도 정보 손실이 없다.** 잃는 것은 재미뿐. 본문이 없으면 조작권 요청을 거부하고 **아이템을 소모시키지 않는다** |
| ⚖️ AI 심판 | `judgment.failed` 이벤트 → 게임 로직의 기본 처형 규칙으로 넘긴다 |
| 🏆 칭호 부여 | 결산 화면을 먼저 띄우고 칭호만 나중에 채운다 (`titlesStatus: PENDING`) |

에러 코드는 [docs/AI-API명세 §3](참고/AI-API명세.md) 에 정리돼 있다. `AI_UNAVAILABLE` (503) 이면 아이템은 롤백이다.

## 8. 검증 함수는 불리언이 아니라 문제 목록을 돌려준다

노트북의 `check_*` 함수 3개가 전부 이 형태다.

```
검증 결과 = 문제 설명 문자열의 리스트. 비어 있으면 통과
```

**어디가 깨졌는지 보여야 프롬프트를 어디를 고칠지 알 수 있다.** 불리언이면 "실패"만 남는다. 프롬프트 튜닝이 작업의 본체인 동안은 이 형태가 값을 한다.

단, **이 검증은 계약 위반만 센다.** 재미·톤·사실 충돌은 사람이 눈으로 본다 (CLAUDE.md — 어서션 러너를 만들지 않는다). 문자열 검사로 자동화하는 것은 **밤 로그 유출 하나**뿐이다.
