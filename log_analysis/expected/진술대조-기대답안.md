# 기대답안 — 진술대조권 (`STATEMENT_COMPARE`)

> 최종 수정: 2026-07-27
> 프롬프트: [진술대조.md](../prompts/진술대조.md)
> 픽스처: [발화로그-공개.txt](../scenario/scenario1/발화로그-공개.txt) · 체크리스트: [테스트-체크리스트.md](../scenario/scenario1/테스트-체크리스트.md)

**문장이 그대로 나와야 한다는 뜻이 아니다.** 아래는 "이런 모양·이런 판정이 나오면 성공"의 참조 샘플이고, 실제 확인은 각 케이스의 **볼 포인트**로 한다.

---

## TC-1 · TC-2 — 초코비 3단 모순 (핵심 케이스)

라면왕이 R3 토론 `21:11:05`에 초코비를 지목한다 (픽스처 실제 사용 기록).

### 입력

아이템 사용 시각 이전, 초코비의 공개 발화 **9건**. `u10`(21:11:35)부터는 사용 시점에 아직 없었으므로 넣지 않는다.

```
u1 [R1] 밤하늘 씨 말도 일리가 있어요 보통 마피아가 먼저 판을 짜려고 하니까
u2 [R1] 저는 딸기우유 씨가 제일 수상해요 아까부터 논의를 계속 막고 있어요 이번 투표는 딸기우유 씨한테 넣을 생각입니다
u3 [R1] 저 방어권 있습니다
u4 [R2] 저는 시민입니다 방어권을 쓴 게 죄가 되나요
u5 [R2] 마음이 바뀐 겁니다 그게 이상한가요
u6 [R2] 딸기우유 씨는 아까부터 논리가 있었어요 저는 처음부터 딸기우유 씨를 믿었습니다
u7 [R2] 저도 딸기우유 씨한테 넣겠습니다
u8 [R3] 저는 딸기우유 씨를 처형하는 데 찬성했습니다 마피아가 동료를 죽이나요
u9 [R3] 저는 딸기우유 씨를 의심한 적이 없습니다 그래서 어제 마음이 아팠어요
```

### 기대 출력 (LLM)

```json
{
  "hasFindings": true,
  "summary": "딸기우유에 대한 태도를 세 라운드에 걸쳐 서로 다르게 진술했습니다.",
  "contradictions": [
    {
      "utteranceIds": ["u2", "u6", "u9"],
      "reason": "1라운드에는 가장 수상하다고 했는데 2라운드에는 처음부터 믿었다고 하고 3라운드에는 의심한 적이 없다고 했습니다."
    },
    {
      "utteranceIds": ["u8", "u9"],
      "reason": "처형에 찬성했다는 진술과 의심한 적이 없다는 진술이 같은 라운드 안에서 양립하지 않습니다."
    }
  ]
}
```

### 서버가 조립한 최종 WS 페이로드

`utteranceIds`를 원문으로 치환하고 봉투를 씌운 결과. 프론트가 받는 건 이것이다.

```jsonc
{
  "requestId": "req_a1b2",
  "itemCode": "STATEMENT_COMPARE",
  "targetPlayerId": "p3",
  "hasFindings": true,
  "result": {
    "summary": "딸기우유에 대한 태도를 세 라운드에 걸쳐 서로 다르게 진술했습니다.",
    "contradictions": [
      { "reason": "1라운드에는 ...",
        "quotes": [
          { "round": 1, "time": "21:01:12", "text": "저는 딸기우유 씨가 제일 수상해요 ..." },
          { "round": 2, "time": "21:06:20", "text": "저는 처음부터 딸기우유 씨를 믿었습니다" },
          { "round": 3, "time": "21:10:45", "text": "저는 딸기우유 씨를 의심한 적이 없습니다 ..." }
        ] }
    ]
  }
}
```

### 볼 포인트

| # | 확인할 것 | 실패하면 |
|---|---|---|
| 1 | `u2` · `u6` · `u9`가 **다 등장**하는가 | 한두 개만 잡으면 3단 모순을 못 본 것. 묶음이 1개든 3개로 쪼개졌든 상관없다 |
| 2 | **`u5`를 모순으로 잡지 않았는가** ← 규칙 4 검증 | "마음이 바뀐 겁니다"는 의견 변경 해명이지 모순이 아니다. 이걸 잡으면 정상적인 생각 변화까지 모순 처리하는 것이므로 System 규칙 4를 강화한다 |
| 3 | `u1`~`u9` **밖의 번호가 없는가** | 없는 발화를 지목한 것. 번호 방식을 쓴 이유가 무너진다 |
| 4 | `reason`에 **역할 추정이 섞이지 않았는가** | "초코비는 마피아로 보입니다" 류가 나오면 규칙 5 위반. 판정은 시민이 해야 한다 |
| 5 | `summary`가 한 문장인가, 길어지지 않았는가 | 화면 공간 문제. 프롬프트에 글자 수 상한을 명시한다 |

## TC-5 — 모순 없음 (정직하게 없다고 하는가)

곰돌이의 **미사용** `STATEMENT_COMPARE`로 R3에 라면왕을 지목한 가정 케이스.

라면왕은 게임 내내 일관된 추리만 한다 (R1 "딸기우유 반응이 빠르다" → R2 "말과 행동이 달랐다" → R3 "초코비가다"). 대상이 바뀌지만 **새 근거가 생겨서 바뀐 것**이므로 모순이 아니다.

```json
{ "hasFindings": false, "noFindingReason": "NO_CONTRADICTION", "contradictions": [] }
```

**볼 포인트** — 없는 모순을 만들어내는지가 전부다. 특히 R1에 딸기우유를 의심했다가 R3에 초코비를 지목한 것을 "의심 대상이 바뀌었다 = 모순"으로 잡으면 **실패**다. TC-1의 초코비(과거 진술을 다르게 말함)과 라면왕(새 근거로 판단이 바뀜)을 구분하는 것이 이 프롬프트의 성능이다.

## TC-4 — 발화 부족 (LLM 호출 없음)

소금빵 지목. R1 토론 기준 소금빵의 공개 발화는 **2건 · 약 25자**.

```
저는 잘 모르겠어요                    (21:01:45)
초코비 씨가 좀 이상한 것 같아요        (21:02:50)
```

임계값(3건 미만 또는 40자 미만) 미달 → **LLM을 호출하지 않고** 서버가 즉시 응답한다.

```json
{ "hasFindings": false, "noFindingReason": "INSUFFICIENT", "contradictions": [] }
```

**볼 포인트** — LLM 호출 로그가 아예 남지 않아야 한다. 호출됐다면 임계값 검사가 동작하지 않은 것이다. 체크리스트가 "가장 위험한 실패 모드"로 지목한 억지 모순 생성은, 애초에 호출하지 않으면 발생할 수 없다.

## TC-6 — R1 사용 시 (설계 재검토가 필요한 발견)

R1 토론은 `21:03:03`에 끝난다. 그 시점까지 각자의 발화 수를 세어보면:

| 대상 | R1 토론 중 발화 수 | 임계값 통과 |
|---|---|---|
| 딸기우유 | 4건 | ✅ |
| 곰돌이 | 4건 | ✅ |
| 라면왕 | 3건 | ✅ (경계) |
| 밤하늘 | 2건 | ❌ |
| **초코비** | **2건** | ❌ |
| 소금빵 | 2건 | ❌ |

→ **R1에는 절반이 임계값 미달이고, 통과해도 대조할 이전 라운드가 없다.** 진술대조권은 실질적으로 R2부터 쓸모가 있는 아이템이다.

시나리오 설정이 이 아이템을 R3에 배치한 판단은 맞았다. 다만 **게임 설계 차원의 결정이 하나 필요하다** — R1 토론에 진술대조권 버튼을 아예 비활성화할지, 아니면 눌리게 두고 "분석할 발언이 부족합니다"로 아이템을 소모시킬지. 후자면 유저가 아이템을 낭비한다.

## 실측 결과 (2026-07-28 · `gpt-5.4-mini`)

`ai-lab`의 `StatementComparePromptTest`로 돌렸다. 프롬프트 변경 이력과 실패한 시도는 [프롬프트 문서 §2-1](../prompts/진술대조.md)에 있다.

| 케이스 | 결과 |
|---|---|
| TC-1·2 | 볼 포인트 1~5 통과. 2회 연속 확인 |
| TC-5 | `hasFindings: false` · `NO_CONTRADICTION` — 없는 모순을 만들지 않았다 |
| TC-4 | LLM 호출 없음. 서버가 `INSUFFICIENT` 즉시 응답 |

실제로 나온 TC-1 출력 한 예 (묶음이 2개로 나왔다).

```
summary : u2의 딸기우유 의심·투표와 신뢰 발언이 충돌하고, 시민 주장과 처형 찬성 설명도 충돌합니다.
· [u2, u6, u7, u9]  u2와 u7은 딸기우유 씨에 대한 투표 입장이 서로 반대이고, u6과 u9는
                    딸기우유 씨를 처음부터 믿었거나 의심한 적이 없다고 하여 u2의 의심·투표와
                    양립하지 않습니다.
· [u4, u8]          u4는 시민이라고 하고 u8은 딸기우유 씨 처형 찬성을 마피아가 동료를 죽이는
                    일로 설명해, 같은 대상에 대한 자신의 입장이 서로 맞지 않습니다.
```

**볼 포인트에 걸리지 않은 문제 두 가지.**

1. **곁가지 거짓 양성이 실행마다 한두 개 섞인다.** 위 예의 `[u4, u8]`도 "모순"이라고 보기 어렵다. 볼 포인트는 *잡아야 할 것*과 *잡으면 안 되는 것*(`u5`)만 보고 있어서, **그 외에 뭐가 더 붙어 나오는지는 검사하지 않는다.** 화면에는 그것까지 나간다
2. **볼 포인트 4(역할 추정)를 단어 검사로는 판정할 수 없다.** 위 `[u4, u8]`의 reason에는 "시민"·"마피아"가 들어 있지만 이건 발화 내용을 옮긴 것이고 역할 추정은 아니다. 테스트에서는 어서션이 아니라 눈으로 볼 표시로만 두었다

**출력이 매번 다르다.** `temperature=0`인데 연속 두 실행의 묶음 구성이 달랐다 → [LLM호출설정 §3](../../docs/LLM호출설정.md). **한 번 통과를 통과로 보면 안 된다.**

응답 시간은 발화 9건에서 1.9~3.3초, 15건(라면왕)에서 3.8초.
