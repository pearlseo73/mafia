# 백엔드 — STT 발화 수집 인수인계

화상 마피아 게임 **사건파일601**의 AI 기능 5종(조간신문 · AI 심판 · 진술대조권 · 키워드 뽑기 · 칭호 부여)은 **모두 같은 발화 로그 하나**를 입력으로 쓴다. **AI 파트는 Redis 에 있는 것만 읽는다** — 거기까지 채우는 것이 백엔드 몫이다.

**한 줄 요약 — 프론트가 보낸 텍스트에 `speaker` · `round` · `phase` · 시각을 붙여 Redis 키 2개 중 하나에 시간순으로 쌓고, TTL 을 건다.** 원문은 MySQL 에 넣지 않는다.

## 2. 계약 샘플 — 이 모양으로 쌓으면 된다

[fixture/](fixture/) 에 한 판 전체가 들어 있다. **AI 파트가 프롬프트를 검증할 때 쓰는 실제 입력**이고, JSON Lines 라 한 줄이 발화 한 건이다.

| 파일 | 대응 Redis 키 | 규모 |
|---|---|---|
| [발화로그-공개-STT.jsonl](fixture/발화로그-공개-STT.jsonl) | `utt:{roomId}:public` | **79건 1,967자** (6명 3라운드) |
| [발화로그-밤마피아-STT.jsonl](fixture/발화로그-밤마피아-STT.jsonl) | `utt:{roomId}:night` | 9건 197자 |

```jsonc
{ "t": "21:06:20", "speaker": "초코비", "round": 2,
  "phase": "DAY_DISCUSSION", "text": "마음이 바뀐 겁니다 그게 이상한가요" }
```

**필드 5개가 전부다.** 그중 `text` 만 클라이언트가 보내고 나머지 4개는 서버가 붙인다.

**규모는 작다** — 한 판 전체가 12KB다. 사람별·라운드별로 쪼개지 말고 키 2개에 전부 쌓은 뒤 꺼내서 걸러 쓴다. 쪼개면 키가 72개가 되고, 전체 대화를 복원할 때 시각순 병합 코드가 필요해지는데 그게 틀리면 **순서가 어긋난 로그로 AI 가 판단한다.**

> 텍스트가 좀 이상해 보이는 것은 오타가 아니다. **브라우저 STT 오인식을 실측대로 심어둔 것**이다 (`찬성했습니다` → `편성했습니다`). 실제 서비스에 들어올 입력이 이 수준이다.

## 3. 🔴 절대 규칙 — 이거 하나만 지켜지면 나머지는 고칠 수 있다

### 밤 발화가 `:public` 에 들어가면 마피아 신원이 그대로 노출된다

```
utt:{roomId}:public    낮 계열 전부
utt:{roomId}:night     밤 마피아 대화만
```

**하나의 리스트에 `visibility` 필드를 두고 조회할 때 거르는 방식은 채택하지 않았다.** 언젠가 필터를 빠뜨린 쿼리가 하나 생기고, 그게 곧 신원 노출이다. **키가 애초에 다르면 실수해도 새지 않는다** (명세 21-2).

| `phase` | 어디로 |
|---|---|
| `DAY_START` · `DAY_DISCUSSION` · `DAY_VOTE` · `AI_JUDGMENT` · `FINAL_DEFENSE` · `RESULT` | `:public` |
| `NIGHT` + 발화자가 **마피아** | `:night` |
| `NIGHT` + 발화자가 **시민** | **버린다** (애초에 전송되지 않아야 하는 발화) |

**밤 → 낮 경계에 버퍼를 둬야 한다.** STT 는 말이 끝난 뒤에 결과를 주므로, 전환 직전에 시작한 발화가 직후에 도착하면 phase 가 하나 밀린다. 낮 안에서(토론 → 투표) 몇 초 밀리는 건 문제가 없지만 **밤 발화가 낮 키에 들어가면 끝이다.** 의심스러우면 밤으로 취급한다 — 낮 로그에서 한 건 빠지는 손해가 신원 노출보다 작다.

**`startedAt` / `endedAt` 을 키 선택에 쓰지 않는다.** 클라이언트 시각을 믿으면 마피아가 자기 낮 발화를 밤으로 위장해 **진술대조권의 사정거리에서 빼낼 수 있다.**

---

## 4. `phase` 는 필수 필드다 — 없으면 기능이 깨진다

가장 중요한 요청 사항이라 따로 적는다. **`round` 와 함께 `phase` 도 저장해달라는 것**이고, 서버가 이미 판정하는 값이라 추가 비용이 없다.

투표 단계의 `"저는 딸기우유 씨입니다"` 는 **투표 선언**인데, `phase` 가 없으면 AI 가 `"나는 딸기우유다"` 라는 **정체 주장으로 읽고** 다른 발언과 모순이라고 답한다. 즉 **하지 않은 주장을 만들어낸 뒤 그것과 모순을 찾는다.**

| | 결과 |
|---|---|
| `phase` 없음 | 모순이 없는 인물을 지목했을 때 **3회 중 3회** 오답 |
| `phase` 있음 | **3회 중 0회** — 사라졌다 |

주어 생략이 흔한 한국어에서 문장만으로는 두 해석을 가릴 수 없다. **AI 가 추측할 문제가 아니라 서버가 알려줄 사실이다.** 저장 시점에 붙이는 것이 정석이고, 투표 시작·종료 시각으로 역산하는 우회로는 우회로다.

---

## 5. 원문을 영구 저장하지 않는다

**발화 원문을 MySQL 에 넣지 않는다.** 음성에서 나온 텍스트는 개인정보이고 게임이 끝나면 필요가 없다. MySQL 에 넣으면 지우는 코드를 따로 만들어야 하고, 안 지우면 계속 쌓인다.

- Redis 두 키 모두 **TTL** (게임 종료 + 여유). 구체값은 §7 미결
- MySQL 에는 **승패 · 통계 · 칭호**만 남긴다

---

## 6. 완료 기준

- [ ] `utt:{roomId}:public` 에 필드 5개가 다 채워져 시간순으로 쌓인다
- [ ] **`phase` 가 7종 중 하나로 정확히 붙는다** — 특히 `DAY_VOTE` 와 `FINAL_DEFENSE` 구분
- [ ] 밤 마피아 발화가 `:night` 로만 간다 → **`:public` 을 전량 덤프해 밤 발화 문구를 문자열로 검색했을 때 0건**
- [ ] 밤 시민 발화가 어느 키에도 남지 않는다
- [ ] 두 키에 TTL 이 걸려 있고 게임 종료 후 만료된다
- [ ] MySQL 어느 테이블에도 발화 원문이 없다

마지막 두 항목은 **눈으로 보지 말고 문자열 검색으로 자동화**하는 것을 권한다. AI 파트도 같은 검사를 최우선 회귀 테스트로 돌린다 — 눈으로는 놓치고, 한 줄만 새면 치명적이다. [fixture/발화로그-밤마피아-STT.jsonl](fixture/발화로그-밤마피아-STT.jsonl) 의 문구를 검사 대상으로 쓰면 된다.

## 7. 정해야 할 것 — 회의 안건

| 항목 | 메모 |
|---|---|
| **TTL 구체값** | 결산·재접속 복구가 끝나는 시점보다 넉넉해야 한다 |
| **시각 필드 형식** | `t` 를 `HH:MM:SS` 문자열로 둘지 epoch ms 로 둘지. **자정을 넘기면 문자열 비교가 깨진다** → AI 쪽 컷오프 코드에 영향이 있어 **먼저 정해야 한다** |
| **밤 → 낮 경계 버퍼** | 몇 초를 밤으로 취급할지 |
| **`text` 500자 초과 처리** | 절단인지 폐기인지. STT 는 문장을 합쳐서 오므로 실제로 길어질 수 있다 |
| **밤 시민 마이크 차단 주체** | 프론트가 인식기를 끄는지, 서버가 버리는지 (**둘 다 권장**) |
| **WS 개별 전송 방식** | 아이템 결과는 **본인만**, 신문 미리보기는 **조작권 소지자만** 받는다. STOMP `user destination` 인지 세션 레지스트리인지 확인이 필요하다 → [AI-API명세 §5-4](AI-API명세.md). **브로드캐스트만 가능한 구조면 두 기능이 성립하지 않는다** |
