# 07. 검증 체크리스트 — 이식이 끝났는지 판정하는 기준

> 관련: [테스트-체크리스트 TC-1~TC-30](참고/테스트-체크리스트.md)

**순서가 중요하다.** ①을 통과하지 않고 LLM 을 붙이면, 결과가 노트북과 달라도 프롬프트 탓인지 렌더 탓인지 구분할 수 없다.

---

## ① 프롬프트가 그대로 갔는가 — LLM 없이 판정

### 1-1. `.st` 파일 10개를 그대로 복사했는가

```
prompts/*.st  →  src/main/resources/prompts/
```

- [ ] 10개 다 있다
- [ ] **파일이 UTF-8 이고 한글이 안 깨졌다**
- [ ] 파일 크기가 아래와 같다 (한 글자라도 다르면 노트북 실측이 보장되지 않는다)

| 파일 | 글자 수 | 중괄호 |
|---|---|---|
| `statement-compare-system.st` | 408 | 2쌍 (JSON) |
| `statement-compare-user.st` | 59 | `log` `target` |
| `keyword-extract-system.st` | 994 | 2쌍 (JSON) |
| `keyword-extract-user.st` | 55 | `target` `now` `utterances` |
| `newspaper-system.st` | 2,396 | 없음 |
| `newspaper-user.st` | 60 | `log` |
| `ai-judge-system.st` | 1,930 | 1쌍 (`{닉네임}`) |
| `ai-judge-user.st` | 614 | `alive_players` `player_statistics` `public_day_utterances` |
| `title-award-system.st` | 1,678 | 2쌍 (JSON) |
| `title-award-user.st` | 799 | `winner` `players` `votes` `public_day_utterances` |

### 1-2. 🔴 SYSTEM 이 렌더를 안 거치는가

- [ ] SYSTEM 5개를 **문자열로 읽어** `.system(String)` 에 넘긴다
- [ ] **실제로 보내는 SYSTEM 문자열을 찍어서 JSON 예시가 살아 있는지 눈으로 본다**
  - `statement-compare` — `{"hasFindings": true, ...}` 두 개가 있어야 한다
  - `keyword-extract` — `{"keywords": [...]}` 가 있어야 한다
  - `title-award` — `{"titles": [...]}` 가 있어야 한다
  - `ai-judge` — `처형 대상은 {닉네임}입니다.` 가 있어야 한다
- [ ] USER 5개만 `.param()` 으로 렌더한다

**이 검사를 건너뛰면 나중에 "왜 JSON 이 안 오지" 로 돌아온다.**

## ② 렌더가 글자 단위로 같은가 — 🔑 가장 중요

같은 픽스처를 넣고 렌더 결과를 [렌더스냅샷/](렌더스냅샷/) 과 비교한다. **LLM 을 부르지 않는다.**

| 스냅샷 | 조건 | 크기 |
|---|---|---|
| `진술대조-초코비-user.txt` | 대상 초코비 · `now=21:11:05` | 513자 11줄 |
| `키워드-딸기우유-user.txt` | 대상 딸기우유 · `now=21:07:30` | 458자 15줄 |
| `조간신문-R1-user.txt` | R1 낮 | 1,729자 33줄 |
| `AI심판-R1-user.txt` | R1 심판 `21:03:39` | 2,400자 108줄 |
| `칭호-user.txt` | 게임 종료 | 4,894자 175줄 |

**이 5개는 `assertEquals` 를 만들 값어치가 있는 유일한 자리다.** 렌더는 결정적이므로 CLAUDE.md 의 "어서션 러너를 만들지 않는다"(LLM 출력에 대한 규칙)에 해당하지 않는다.

### 어긋나기 쉬운 곳 — 여기부터 본다

- [ ] **진술대조 번호 정렬** — `u1` 앞에 **공백 1칸**, `u10` 은 없다 (폭 3 오른쪽 정렬)
- [ ] **키워드는 정렬이 없다** — `u1`, `u11` 그대로
- [ ] **AI 심판 통계 소수점 1자리** — `17.3%` · `21.3자`
- [ ] **AI 심판 라운드별 구분자** — ` / ` (`R1 6회 / R2 3회`)
- [ ] **칭호 플레이어 정보 들여쓰기** — 공백 2칸
- [ ] 블록 사이 **빈 줄 하나** (통계·플레이어 정보)
- [ ] 페이즈 한글 라벨 (`DAY_DISCUSSION` → `토론`)
- [ ] 조간신문은 `말한사람 X · 발언 Y`, 심판·칭호는 `X: Y` — **기능마다 다르다**
- [ ] 줄바꿈이 `\n` 이다 (`\r\n` 이면 전부 어긋난다)

### 컷오프가 맞는지 함께 확인된다

- [ ] 진술대조 입력에 `21:11:20`(결과를 읽어주는 대사)이 **없다**
- [ ] 진술대조 초코비 발화가 **8건 289자**다
- [ ] 키워드 딸기우유 발화가 **11건**이다
- [ ] AI 심판 컷오프 이전이 **25건 738자**, 심판 구간 발화 4건이 빠졌다
- [ ] 조간신문 R1 이 **28건 780자**다 (`DAY_START`·`RESULT` 제외 → 29건에서 1건 줄어든다)
- [ ] 칭호는 **79건 전체**다

## ③ 밤 로그가 새지 않는가 — 🔴 최우선 회귀 테스트

**한 줄만 새면 마피아 신원이 그대로 노출된다** (TC-12, 명세 21-2).

- [ ] 공통 로더가 `phase != NIGHT` 를 로드 지점에서 확인한다
- [ ] 조간신문 호출 함수 **안에** 유출 검사가 있다 (밖에 두면 빼먹는다)
- [ ] 검사가 **입력과 출력 양쪽**을 본다
- [ ] 검사 어절이 **낮 로그와의 교집합을 뺀 것**이다 (안 빼면 매번 걸려서 무시당한다)
- [ ] 검사 문구를 **STT 변형본 기준**으로 넣었다 ([fixture/발화로그-밤마피아-STT.jsonl](fixture/발화로그-밤마피아-STT.jsonl))
- [ ] **밤 로그를 읽는 코드가 이 검사 말고는 없다** — 칭호도 안 읽는다 (TC-28)
- [ ] 낮 기능 4종의 출력에서 밤 로그 문구를 문자열 검색해 0건 (TC-29)

## ④ 환각 방어가 코드에 있는가

프롬프트 품질과 무관하게 보장되는 것들이다.

- [ ] 🔍 진술대조 — `byId` 밖의 번호를 버린다
- [ ] 🔍 진술대조 — 남은 `ids` 가 2개 미만이면 `hasFindings=false`
- [ ] 🔍 진술대조 — 임계값(3건·40자) 미달이면 **호출하지 않는다**
- [ ] 🏷️ 키워드 — `byId` 번호 검증 (**노트북에 없다. 붙이면서 옮긴다**)
- [ ] 🏷️ 키워드 — evidence 중복 배정 검사 · `count == evidence.size()`
- [ ] ⚖️ 심판 — 생존자 목록 밖의 이름을 버린다
- [ ] ⚖️ 심판 — 판결 이유에 대상 닉네임이 미리 등장하는지 검사
- [ ] 🏆 칭호 — 누락 · 중복 배정 · 없는 닉네임 · 칭호 중복 · 빈 항목
- [ ] 전부 — 파싱 실패를 **예외가 아니라 결과로** 돌린다

## ⑤ 역할이 안 새는가 — 절대 규칙 2

- [ ] 진술대조 · 키워드 · 조간신문 · AI 심판 프롬프트에 **역할 정보가 없다**
- [ ] 이벤트 파서가 기능별로 갈려 있고, 낮 기능용 파서는 `ROLE` 줄을 **읽지 않는다**
- [ ] 조간신문의 결과 줄에 `role` 이 안 들어간다 (코드가 받아서 렌더에서 버린다)
- [ ] 칭호만 `ROLE` 을 읽는다
- [ ] **정답률이 비정상적으로 높으면 유출을 의심한다** — 심판이 마피아를 반복해서 정확히 찍으면 입력을 다시 본다

## ⑥ LLM 을 붙이고 나서

**같은 케이스를 2회 이상 돌린다.** `temperature=0` 이어도 실행마다 출력이 달라진다 — 매번 나오는 것과 그 회차에만 나온 것을 구별해야 한다.

| 기능 | 케이스 | 기대 | TC |
|---|---|---|---|
| 🔍 | 초코비 `now=21:11:05` | 모순 있음 — `u2`×`u5` 또는 `u7`×`u8` | TC-1 · TC-2 |
| 🔍 | 라면왕 `now=21:11:05` | **모순 없음** | TC-5 |
| 🔍 | 소금빵 `now=21:11:05` | `INSUFFICIENT` (호출 없음) | TC-4 |
| 🏷️ | 딸기우유 `now=21:07:30` | 5개 · evidence 중복 배정 없음 | TC-8 |
| 📰 | R1 → 제1호 | 헤드라인 1~2 · 본문 2문단 · 인용 1~3 · 500자 이내 · 유출 0 | TC-12 |
| 📰 | R2 → 제2호 | 처형·역할 공개 케이스 (**미검증**) | |
| 📰 | R3 → 제3호 | 무사망 케이스 (**미검증**) | |
| ⚖️ | R1 심판 | 형식 5종 통과 · 대상이 생존자 | |
| 🏆 | 게임 종료 | 6명 정확히 한 번 · 칭호 중복 없음 | TC-25 · TC-26 |

### 응답 시간도 함께 잰다

| 기능 | 노트북 실측 |
|---|---|
| 🔍 진술대조 | 1.9~3.3초 (발화 9건) · 3.8초 (15건) |
| 🏷️ 키워드 | 1.5~2.5초 |
| 📰 조간신문 | **미측정** — 생성 창이 R1 4초라 이 값이 재시도 예산을 정한다 |
| ⚖️ 심판 | 1.8초 · 스트리밍 첫 글자 1.13초 |
| 🏆 칭호 | 6.0초 |
| **첫 호출** | **4~7초** → 워밍업 필수 |

## ⑦ 통합 — 노트북에 없는 것

노트북에 게임 상태가 없어서 빠진 것들이다. **팀 레포에서 처음 붙는다.**

- [ ] 아이템 사용 권한 검증 7단계 (요청자 생존 · **역할 일치** · phase · 잔여 시간 · 대상 생존 · 다른 액티브 아이템 · 보유 상태) → [AI-API명세 §1-1](참고/AI-API명세.md)
- [ ] 진술대조권은 **시민 전용** (`ITEM_ROLE_MISMATCH` 403)
- [ ] 대상 사망 시 `TARGET_NOT_ALIVE` (TC-7 — 노트북은 소금빵이 사망자인데 임계값까지 흘러가 우연히 같은 결과가 나온다)
- [ ] LLM 실패 시 아이템 롤백 (`AI_UNAVAILABLE` 503)
- [ ] `item.analysis.result` 는 **요청자 본인만** 수신 (T6 확정)
- [ ] `newspaper.preview` 는 **조작권 소지자 한 명만**
- [ ] 발화 번호(`u5`)와 `byId` 는 **서버에만.** 프론트로는 치환된 원문만
- [ ] 칭호 `reason` 은 프론트로 내리지 않는다
- [ ] 방 생성 시 **워밍업 호출**
- [ ] 재접속 스냅샷에 AI 산출물 포함 → [AI-API명세 §4](참고/AI-API명세.md)

## ⑧ ⏸ STT 구현이 끝난 뒤에 확인할 것 — 보류 항목

**이식 중에는 손대지 않는다.** 프론트·백엔드에 넘긴 인수인계를 바꾸지 않기로 했고, 계약을 바꾸지 않고 나중에 AI 쪽만 고칠 수 있는 문제다.

- [ ] **백엔드에게 물어본다 — "발화 ZSET `score` 에 뭐 넣었어?"**
- [ ] epoch(초든 밀리초든)면 → **컷오프 3곳**(진술대조·키워드·AI 심판)을 `score` 비교로 전환한다
- [ ] `210620` 처럼 시각을 숫자로 바꾼 것이면 → `ts` 필드 추가를 요청한다
- [ ] 전환 후 [렌더 스냅샷](렌더스냅샷/) 이 그대로 통과하는지 확인한다 (렌더는 `t` 를 쓰므로 안 바뀌어야 정상)

**왜 필요한가** — `t` 가 `HH:MM:SS` 문자열이라 **자정을 넘기는 판에서 시점 컷오프가 통째로 어긋난다.** 유저에게는 "발언이 부족합니다"로 보이고 로그상으로는 정상처럼 보인다. 상세는 [01-공통.md 보류 항목](01-공통.md).
