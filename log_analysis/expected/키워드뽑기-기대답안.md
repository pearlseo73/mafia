# 기대답안 — 키워드 뽑기 (`KEYWORD_EXTRACT`)

> 최종 수정: 2026-07-27
> 프롬프트: [키워드뽑기.md](../prompts/키워드뽑기.md)
> 픽스처: [발화로그-공개.txt](../scenario/scenario1/발화로그-공개.txt) · 체크리스트: [테스트-체크리스트.md](../scenario/scenario1/테스트-체크리스트.md)

문장이 그대로 나와야 한다는 뜻이 아니다. **이런 모양·이런 판정이면 성공**의 참조 샘플이고, 확인은 각 케이스의 볼 포인트로 한다.

---

## TC-8 — 강예린 키워드 추출 (핵심 케이스)

정민재가 R1 토론 `21:02:09`에 강예린을 지목한다 (픽스처 실제 사용 기록).

### 입력

사용 시각 이전, 강예린의 **R1 발화 4건**. 라운드 표시도 번호도 붙이지 않는다.

```
저는 그런 거 시간 낭비라고 생각해요 그냥 느낌으로 가야죠
아니 그러면 삼분 동안 뭘 어떻게 하겠다는 거예요 다들 시민이라고 할 거잖아요
뭐라고요 제가 뭘 막았다는 거죠 방식이 비효율적이라고 한 거잖아요
억울하면 빠르게 말하는 게 당연하죠 저는 시민이에요
```

임계값(3건·40자) 통과 — 4건 약 110자.

### 기대 출력 (LLM)

```json
{
  "hasFindings": true,
  "keywords": ["시간 낭비", "느낌으로", "비효율적", "억울하면", "시민"]
}
```

### 서버가 조립한 최종 WS 페이로드

```jsonc
{
  "requestId": "req_c3d4",
  "itemCode": "KEYWORD_EXTRACT",
  "targetPlayerId": "p6",
  "hasFindings": true,
  "result": { "keywords": ["시간 낭비", "느낌으로", "비효율적", "억울하면", "시민"] }
}
```

### 볼 포인트

| # | 확인할 것 | 실패하면 |
|---|---|---|
| 1 | 모든 키워드가 **입력 발화의 부분 문자열**인가 (공백 제거 후 비교) | 로그에 없는 단어를 만든 것. 서버 검사에서 걸러지지만, 걸러진 뒤 남는 게 없으면 결과가 빈다 |
| 2 | **상위 개념어가 섞이지 않았는가** — `비협조`, `방어적`, `회피` 같은 것 | 추출이 아니라 해석이다. 프롬프트 규칙 1을 강화한다 |
| 3 | 그 사람의 **태도가 드러나는 표현**인가 | `그러니까`, `저는`, `거예요` 류가 올라오면 규칙 3이 안 먹은 것 |
| 4 | 3~5개인가, 각 10자 이내인가 | 화면 공간 문제 |
| 5 | 판정하지 않았는가 | 키워드 목록에 `마피아 의심` 같은 게 들어오면 규칙 4 위반. 이 아이템은 판정하는 물건이 아니다 |

`시간 낭비`, `느낌으로`, `억울하면`은 [체크리스트 TC-8](../scenario/scenario1/테스트-체크리스트.md)이 지목한 근거 발화와 일치한다. 다섯 개 중 몇 개가 겹치는지보다 **1번과 2번이 중요하다.**

## TC-10 — 라운드 범위 제한 (진술대조권과의 차별점)

같은 대상(강예린)을 **R2 토론**에서 지목한 가정 케이스.

### 입력 — R2 발화만

```
저도 박도현 씨는 아닌 것 같아요 오히려 어제 저를 지목했던 사람이잖아요
그만 좀 하세요 김서준 씨 조용히 좀 해봐요 아이템 쓸게요
그 결과 아무도 못 봤죠 혼자만 봤다고 하는 거잖아요
```

### 기대 출력

```json
{
  "hasFindings": true,
  "keywords": ["박도현 씨는 아닌", "조용히 좀", "혼자만 봤다"]
}
```

### 볼 포인트 — 이 케이스는 이것만 본다

**R1 발화에서 온 키워드(`시간 낭비`, `느낌으로`, `억울하면`)가 하나라도 나오면 실패다.** 로그 조회 범위가 잘못 잡힌 것이고, 그러면 진술대조권과 산출물이 겹쳐 아이템을 두 개 둘 이유가 없어진다.

프롬프트 문제가 아니라 **입력을 만드는 코드의 문제**이므로, 프롬프트를 고치는 게 아니라 조회 범위를 고쳐야 한다.

## TC-9 — 발화 부족 (LLM 호출 없음)

최지우 지목. R1 토론 기준 발화 **2건 · 약 25자**로 임계값(3건·40자) 미달.

```json
{ "hasFindings": false, "noFindingReason": "INSUFFICIENT", "keywords": [] }
```

**볼 포인트** — LLM 호출 로그가 아예 남지 않아야 한다. 진술대조권 TC-4와 같은 장치다.

## 📌 픽스처 문제 두 건 — 결정 필요

문서를 쓰면서 발견했다. **기대답안을 확정하기 전에 정리해야 한다.**

### ① 체크리스트 TC-8의 근거 발화 중 하나가 사용 시각 이후다

[테스트-체크리스트](../scenario/scenario1/테스트-체크리스트.md) TC-8이 근거로 든 네 개 중 `21:02:58` **"근거도 없이"는 아이템 사용(`21:02:09`) 이후 발화**다. 그 시점에 존재하지 않으므로 입력에 들어갈 수 없고, **기대답안에 포함하면 안 된다.**

→ 체크리스트의 근거 목록을 세 개로 고쳐야 한다. (`21:00:15` 시간 낭비·느낌으로 / `21:01:22` 비효율적 / `21:01:38` 억울하면)

### ② 정민재가 공유한 키워드가 강예린의 발화에 없다

픽스처에서 정민재는 결과를 이렇게 공유한다.

> `21:02:45` 강예린 씨 발언에서 **몰아가기**랑 시간 낭비 이런 단어가 계속 나왔어요

그런데 **`몰아가기`는 강예린의 R1 발화에 등장하지 않는다.** 두 가지로 읽을 수 있고, 어느 쪽인지 정해서 문서에 남겨야 한다.

| 해석 | 함의 |
|---|---|
| **픽스처 오류** | `21:02:45`를 실제 키워드로 고친다. 기대답안과 게임 내 대사가 일치하게 된다 |
| **정민재가 결과를 왜곡해 전달** | [로그2안아이디어.txt](../scenario/로그2안아이디어.txt)의 "아이템 사용 결과 왜곡 ★ 게임상 가장 강력한 거짓말"이 1안에 이미 심겨 있는 셈이다. [T6 확정](../../docs/결정필요사항.md)(결과는 본인만 봄)이 이걸 가능하게 만든다 |

**후자가 더 흥미롭지만, 그렇다면 시나리오 설정에 명시해야 한다.** 지금은 정민재가 "추리 주도, 아이템 적극 사용"하는 선의의 시민으로 설정돼 있어서, 결과 왜곡이 의도인지 실수인지 문서만 봐서는 알 수 없다.

> 강예린이 `21:07:25`에 "그 결과 아무도 못 봤죠 혼자만 봤다고 하는 거잖아요"라고 짚는 대사가 이미 있어서, 후자로 정하면 픽스처의 앞뒤가 오히려 잘 맞는다.
