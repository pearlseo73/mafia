Task 1. 방 생성 및 입장
1-1. 방 생성 시 고유 코드와 초대 링크가 발급되고, 생성자(방장)는 즉시 입장한다. 
1-2. 링크는 게임방 ID를 가지고 Base64 인코딩을 통해 만든다.
1-3. 방 고유 코드는 6자리 소문자 + 대문자 + 숫자 랜덤 생성
1-4. 고유 코드 중복 여부를 판단해서 중복 시 랜덤을 다시 돌린다.
1-5. 재생성은 최대 5번 시도하고 실패할경우 사용자에게 실패처리 하도록 한다.
1-6. 코드 수동 입력 또는 붙여넣기로 입장한다.
1-7. 코드에 한글은 입력되지 않는다.
1-8. 초대 링크 접속 시 랜딩 페이지를 생략하고 입장 플로우로 진입한다.
Task 2. 참가자 식별 및 정원 관리
2-1. 신규 참가자는 방마다 닉네임을 새로 설정한다.
2-2. 정원(6명) 초과 시 서버가 에러 코드를 반환하고 클라이언트가 명확한 메시지를 표시한다.
Task 3. 세션 유지 및 재접속
3-1. 게임 시작 시 서버가 세션 토큰을 발급하고(방 마다 세션 관리) 클라이언트는 로컬 스토리지에 보관한다.
3-2. 이탈 감지 시 토큰에 만료 시각(30초)을 부여한다.
3-3. 재접속 시 서버가 토큰 유효성과 잔여 시간을 검증하고, 통과하면 닉네임 입력 없이 게임방으로 복귀한다.
3-4. 게임 종료 시 토큰을 폐기한다.
Task 4. 예외 처리
4-1. 존재하지 않는 방 코드/링크에 대해 오류를 표시한다. (코드 입력 시 인라인 오류, 링크 접속 시 오류 페이지 + 랜딩 페이지 복귀 버튼)
4-2. 이미 시작된 방에 신규 참가자는 입장할 수 없다 (코드 입력 시 인라인 오류, 링크 접속 시 오류 페이지 + 랜딩 페이지 복귀 버튼)


Task 5. 대기 화면 진입 및 닉네임 설정
5-1. 입장 시 닉네임 입력 모달을 표시하며, 유효한 닉네임을 입력하기 전에는 닫을 수 없다.
5-2. 닉네임은 2~8자, 한글/영문/숫자만 허용하며 앞/뒤 공백은 제거한다.
5-3. 같은 방 안에서 닉네임 중복을 허용하지 않으며, 중복 시 인라인 오류를 표시한다.
5-4. 닉네임을 입력하지 않아도 서버에서 입장 처리는 한다.
5-5. 닉네임을 입력한 후에 화면상에 표시한다.
5-6. 모달에서 획득한 미디어 스트림은 대기 화면에서 그대로 재사용한다.
Task 6. 플레이어 화면 구성
6-1. 화면 가운데에 각 참가자의 영상과 닉네임을 표시한다. 
6-2. 서버는 참가자에게 재사용하지 않는 입장 순번(joinSeq)을 부여하고, 화면 배치는 순번 오름차순을 따른다.
6-3. 참가자가 나가면 빈자리를 앞으로 당겨 재배치한다.
6-4. 영상을 받지 못하면 디폴트 이미지를 표시하고, 카메라를 끈 경우와 수신 실패를 서로 다른 배지로 구분한다.
6-5. 발화 시 해당 참가자의 화면 테두리가 초록색으로 빛난다.
6-6. 발화 판정은 각 클라이언트가 수신 오디오를 분석하며, 켜짐/꺼짐 임계값을 다르게 두어 깜빡임을 막는다.
6-7. 방장 화면에 방장 표시를 한다.
Task 7. 준비 상태 및 게임 시작
7-1. 카메라와 마이크 권한을 요청받는다.
7-2. 사용자는 카메라와 마이크를 켜고 끌 수 있으며, 둘 다 켜야 준비 상태로 자동 전환된다.
7-3. 각 플레이어의 Ready 여부를 화면에 표시한다. 
7-4. 준비 이후 카메라 혹은 마이크를 끄면 준비 상태는 해제된다.
7-5. 권한 거부 등으로 준비에 실패하면 원인과 재시도 방법을 텍스트 문구로 안내한다.
7-6. 방장 화면 하단에 start 버튼을, 그 외 참가자에게는 같은 위치에 waiting...을 표시한다.
7-7. 최소 인원 미달이거나 미준비 참가자가 있으면 start 버튼은 회색 비활성 상태가 된다.
7-8. 게임 시작 조건을 만족하면 start 버튼이 빨간색 활성 상태가 되며, 방장이 누르면 게임이 시작된다.
Task 8. 방장 권한 및 방 생명주기
8-1. 방장이 나가면 남은 참가자 중 입장 순번이 가장 빠른 사람이 방장 권한을 얻는다.
8-2. 방장이 혼자 있을 때 나가면 방을 삭제한다.
8-3. 일정 시간 이상 참가자가 없는 방은 서버가 정리한다.
8-4. 방이 삭제되면 해당 코드를 재사용할 수 있으며, 코드 유일성 제약은 활성 상태의 방에만 적용한다.
Task 9. 미디어 제어
9-1. start 버튼 하단에 자신의 카메라와 마이크 상태를 표시하고 켜고 끌 수 있다.
9-2. 카메라, 마이크 버튼 하단에 있는 마이크와 사운드 볼륨 바로 입/출력 음량을 조절할 수 있다. 
9-3. 다른 참가자가 카메라나 마이크를 끈 상태를 해당 참가자 화면에 표시한다.
Task 10. 방 정보 공유
10-1. 화면 우측 상단에 방 코드와 초대 링크를 표시한다.
10-2. 초대 링크는 방 코드를 경로에 담아 생성한다.
10-3. 링크 공유 클릭 시 팝오버(텍스트 + 복사 버튼)를 표시한다.
Task 11. 대기 화면 채팅
11-1. 화면 우측 채팅창에서 참가자 대화와 시스템 알림을 함께 확인할 수 있다.
11-2. 시스템 알림은 입장, 퇴장, 방장 위임, 공지사항을 표시한다.
11-3. 대기 화면 채팅 내용은 게임 시작 시 초기화한다.
Task 12. 대기 화면 이탈 처리
12-1. 연결이 끊긴 참가자의 자리는 유예 시간 동안 유지하고 재접속 대기 상태를 표시한다.
12-2. 유예 시간 안에 재접속하면 기존 입장 순번과 방장 권한을 복구한다.
12-3. 유예 시간이 지나면 정식 퇴장으로 처리한다.
Opitional : 강퇴 기능 + 닉네임 안정했을 떄는 클라이언트 단에서 로딩바로 표시  

Task 13. 게임 진행 플로우
13-1. 게임은 낮 시작 → 낮 토론 → 낮 투표 → 최후 변론 또는 AI 심판 → 밤 순서로 순환한다.
13-2. 낮 토론은 3분, 낮 투표는 30초, 최후 변론은 30초, 밤은 30초로 진행한다.
13-3. 세션이 전환될 때 3초의 텀과 함께 fog 효과를 표시한다.
13-4. 세션 전환이나 이벤트 발생 시 시스템 알림에 띄워준다.
13-5. 모든 세션의 진행 상태와 남은 시간은 서버를 기준으로 삼는다.
13-6. 마피아 수와 시민 수가 같아지면 마피아가 승리한다.
13-7. 마피아가 모두 사망하면 시민이 승리한다.
13-8. 승리 조건은 사망이 확정되는 시점(낮 처형, 밤 사망)마다 서버가 판정하고, 충족되면 즉시 게임을 종료한다.

Task 14. 게임 정보 표시
14-1. 화면 상단에 낮/밤 구분, 라운드, 현재 상태, 남은 시간, 스킵버튼을 표시한다.
14-2. 스킵 버튼은 토론시간에만 활성화된다.
14-3. 한 토론 세션에서 인 당 한 번만 스킵 버튼을 누를 수 있으며, 누르면 전체 토론시간에서 10초가 차감된다.
14-4. 남은 시간이 10초 미만에서 스킵버튼을 누르거나 전원이 스킵버튼을 누른 경우, 투표를 진행한다.
14-5. 클라이언트는 서버가 내려준 값을 기준으로 표시하며, 자체 타이머는 보간 용도로만 쓴다.
14-6. 죽은 사람은 마이크와 캠코더를 모두 차단하고 캠 위치에 죽었음을 표시하는 이미지 삽입

Task 15. 게임 중 채팅 및 시스템 로그
15-1. 화면 우측에 채팅창이 있다.
15-2. 채팅창의 카테고리는 시스템, 유령 채팅, 메모장으로 구분한다.
15-3. 카테고리별 필터링을 지원하며, 선택하지 않았을 때 기본값은 시스템으로 한다.
15-4. 시스템 로그는 전체 공지와 아이템 사용 로그로 구분해 표시한다.
15-5. 아이템 사용공지를 텍스트로 전달한다.
15-6. 엔터로 Input 메시지를 전송하고, Shift + 엔터로 줄바꿈한다.
15-7. Input 메시지는 최대 100자로 제한한다. 
15-8. 각 메시지에 발생 시각을 타임스탬프로 표시한다.
15-9. 채팅 이력은 스크롤 형식으로 표시한다.
한 판 동안의 이력은 계속 확인 가능하다.

Task 16. 아이템
16-1. 화면 하단에 아이템 리스트를 한눈에 파악할 수 있도록 배치한다.
16-2. 아이템은 패시브와 액티브로 구분하며, 패시브는 왼쪽, 액티브는 오른쪽에 배치한다.
16-3. 아이템 카드 범위에 마우스를 올리면 아이템 설명을 표시한다.
16-4. 아이템 상태는 사용 가능, 사용 중, 사용 완료, 사용 불가로 구분한다.
16-5. 액티브 아이템의 경우 아이템을 클릭해 발동한 뒤 대상 플레이어의 화면을 클릭해 사용한다.
16-6. 사용 중 상태에서 사용 가능 상태로 되돌릴 수 있다.
=> 아이템 발동 조건이 만족되지 않는 모든 경우에는 사용 가능 상태로 롤백한다.
선택된 아이템 카드를 다시 클릭 (토글)
대상 플레이어가 아닌 게임 화면의 빈 배경 또는 다른 아이템 클릭
토론 중 아이템 사용 대상 지정 대기 중, 투표로 넘어간다면 대기 중이었던 아이템은 사용 취소 처리
16-7. 플레이어 한 명이 아이템을 사용 중일 때 그 사람은 다른 아이템을 사용할 수 없다.
(단, 패시브는 제외)
16-8. 아이템의 현재 상태와 동일한 상태 변경 요청은 무시한다.
16-9. 액티브 && 사용자 지목 아이템은 나 자신에게도 사용 가능하다.
16-10. 플레이어가 사망한 경우, 소지한 모든 아이템을 사용완료(==삭제) 처리

Task 17. 신문
17-1. 신문은 낮 투표 시작할 때 STT 로그를 기반으로 AI가 생성한다. (추후 조정 가능)
17-2. 신문 텍스트는 최대 1000자로 제한한다.
17-3. 밤 시작 시 마피아에게만 채팅창에 신문 내용을 표시한다.
17-4. 마피아는 조작 아이템을 사용해 밤에 신문 텍스트를 수정할 수 있다.
17-5. 마피아가 신문 편집은 언제나 가능하지만, 반드시 Apply를 눌러야 내용이 최종 반영되고 아이템 사용 완료 처리된다. 
17-6. 낮 시작 시 신문을 화면 가운데에 표시하고 10초 뒤 닫는다. (모달 아님)
17-7. LLM이 생성했던 내용에 누가 죽었는지를 고정 템플릿으로 넣는다. 단, 아무도 안죽었으면 평화로운 밤입니다~~

Task 18. 낮 투표
18-1. 낮 투표는 30초간 진행하며, 투표 현황은 공개하지 않는다.
18-2. 제한 시간 종료 후 전체 투표 결과를 집계해 화면에 표시한다.
18-3. 플레이어의 캠을 클릭하면 확인 모달을 표시한다.
18-4. 확인 모달에 주의사항을 텍스트로 안내하고 예/아니오 버튼으로 확정한다.
18-5. 자기가 투표 확정한 대상의 테두리에 본인에게만 빨간 테두리를 표시한다.
18-6. 한 번 확정한 투표는 변경할 수 없다.
18-7. 제한 시간 내에 투표하지 않거나 AI 위임버튼을 누르면 AI위임으로 처리한다.
18-8. 최다 득표자가 특정되면 최후 변론으로, 특정되지 않으면 AI 심판으로 진행한다.
18-9. 낮 투표의 결과로 최후 변론 또는 AI 심판으로 연결되는데, 이때 시스템 알림을 띄운다.

Task 19. 최후 변론
19-1. 최다 득표자의 화면을 좌측에, AI 얼굴 분석 결과를 우측에 표시한다.
19-2. 최후 변론 시간은 30초로 한다.
19-3. 얼굴 분석은 별도 서버 없이 클라이언트에서 처리해 실시간성을 확보한다.
19-4. 별도의 투표 시간 없이 우측 하단의 찬성/반대 버튼으로 투표하고, 내가
어떤 버튼을 눌렀는지 표시
19-5. 한번 결정한 투표는 변경할 수 없다.
19-6. 제한 시간 내에 투표하지 않으면 반대로 처리한다.
19-7. 제한 시간 종료 후 투표 결과를 3초간 표시한다.
19-8. 찬성이 과반이면 처형 연출을, 그렇지 않으면 처형되지 않는 연출을 3초간 표시한다.

Task 20. AI 심판
20-1. 최다 득표자가 특정되지 않은 경우 전체 인원을 대상으로 AI 심판이 진행된다.
20-2. AI는 STT 로그를 분석해 마피아일 가능성이 가장 높은 플레이어를 선정해 처형한다.
20-3. AI 심판시 화면 중앙을 이분할하여 좌측에는 심판 대상인의 얼굴을 표시하고 우측에는 심판 사유와 처형대상인을 텍스트로 발표한다.
