# AI 담당자 학습 로드맵

> 최종 수정: 2026-07-26
> 관련 문서: [기술스택-검토.md](기술스택-검토.md) · [AI기능-구현설계.md](AI기능-구현설계.md)

WebRTC·WebSocket을 직접 구현하지는 않지만, **AI 코드가 그 위에 올라가므로** 개념을 모르면 설계가 성립하지 않는 항목들이 있다. 각 항목에 "내 코드의 어디가 이것에 의존하는지"를 붙였다.

---

## A. 반드시 — 내 코드가 직접 의존

### A-1. WebRTC: 로컬 스트림 vs 원격 스트림

구현하지 않더라도 이 구분은 알아야 한다. **얼굴 분석 설계 전체가 여기에 걸려 있다.**

- 원격 스트림(SFU 경유)은 압축·프레임 드랍이 있어 추론 품질이 떨어진다
- 그래서 [결정필요사항 T10](결정필요사항.md)에서 "대상자 본인이 **로컬** 스트림으로 계산"을 권했다

**필요한 범위:** `getUserMedia`, `MediaStream` / `MediaStreamTrack`, SFU가 하는 일. 시그널링·ICE·TURN 내부까지는 불필요.

### A-2. LiveKit Client SDK — track attach

face-api.js에 넘길 `<video>` 엘리먼트를 LiveKit에서 받아와야 한다. `track.attach()`가 반환하는 엘리먼트를 composable에 주입하는 구조가 된다.

**필요한 범위:** Room 접속, track 구독/발행, `attach()` / `detach()`, 이벤트 리스너.

### A-3. Web Audio API — `AnalyserNode`

명세 6-5·6-6(발화 시 초록 테두리, 켜짐/꺼짐 임계값 분리로 깜빡임 방지)은 STT와 **별개의** 오디오 레벨 분석을 요구한다. AI 파트로 넘어올 가능성이 높다.

더 중요한 이유: **마이크 트랙 하나를 LiveKit + Web Speech API + AnalyserNode 셋이 공유**한다. 여기서 충돌이 나면 최대 리스크 항목과 직결된다.

**필요한 범위:** `AudioContext`, `createMediaStreamSource`, `AnalyserNode`(`getByteFrequencyData` / RMS 계산), 히스테리시스 구현.

### A-4. WebSocket — 특히 "특정 유저에게만 전송"

[결정필요사항 T6](결정필요사항.md)(진술대조 결과를 본인에게만 표시)이 여기 걸려 있다. **브로드캐스트만 알면 T6를 구현할 수 없다.**

- Spring이 STOMP를 쓰면 `/user/queue/...` user destination
- raw WebSocket이면 세션 레지스트리를 직접 관리

밤 마피아 채팅(21-2)·유령 채팅(15-2)도 같은 문제라 백엔드 담당과 겹친다. **먼저 확인하고 공유할 것.**

### A-5. Spring 비동기 HTTP 호출

LLM 호출은 초 단위다. 3분 토론 중 6명이 아이템을 쓰면 동시 호출이 들어오고, 톰캣 스레드를 블로킹하면 게임 전체가 멈춘다.

**필요한 범위:** `WebClient`(논블로킹), 타임아웃 설정, 재시도(Resilience4j 또는 Reactor `retryWhen`), `Flux`로 스트리밍 받기.

### A-6. Spring AI

| 항목 | 쓰이는 곳 |
|---|---|
| `ChatClient` fluent API | 전 기능 |
| `.entity(Class)` — 구조화 출력 | 칭호 배정, AI 심판 결과, 키워드 목록 |
| `.stream()` → `Flux<String>` | AI 심판 (명세 20-5) |
| `PromptTemplate` + 리소스 파일 | 프롬프트 버전 관리 |

**주의:** 대화 메모리(Advisor·ChatMemory)는 필요하지 않다. 모든 호출이 단발성 stateless다. 튜토리얼을 따라 챗봇 구조를 만들면 불필요한 복잡도가 붙는다.

## B. 알아야 협업이 된다

### B-1. Redis 데이터 구조

발화 로그를 "3라운드 토론 구간만" 가져오는 것이 ZSET score 범위 조회로 해결된다.

**필요한 범위:** ZSET(`ZRANGEBYSCORE`), TTL, Spring Data Redis(`RedisTemplate`). 멀티 인스턴스로 가면 Pub/Sub.

### B-2. LLM 스트리밍 릴레이 방식 (SSE vs WebSocket)

AI 심판은 전원이 동시에 봐야 하므로, 서버가 GPT 스트림을 받아 **WebSocket으로 브로드캐스트**하는 쪽이 자연스럽다. SSE는 1:1 연결이라 이 용도에 맞지 않는다.

### B-3. OpenAI API 실무

**필요한 범위:** rate limit(429) 처리, 토큰 비용 계산, temperature, 스트리밍 응답 형식. [결정필요사항 T12](결정필요사항.md)가 이 얘기다.

### B-4. 프롬프트 엔지니어링

한국어 게임 컨텍스트에서의 환각 억제가 핵심 과제다. 대표 사례: 침묵한 플레이어에게 LLM이 억지 모순을 만들어내는 문제([AI기능-구현설계 §7-5](AI기능-구현설계.md)).

**필요한 범위:** JSON 스키마 강제, few-shot, "해당 없음"을 정상 출력으로 명시하는 지시 설계, 입력 로그 포맷팅.

## 학습과 작업을 겹치는 방법

**STT × LiveKit 마이크 공존 PoC를 첫 작업으로 잡으면 A-1·A-2·A-3을 자연스럽게 훑는다.**

Vue + LiveKit 최소 예제에 `webkitSpeechRecognition`을 붙여 마이크가 둘 다 잡히는지 확인하는 작업이, 그대로 로컬/원격 스트림 구분 · track attach · 오디오 트랙 공유를 다루게 된다. 최대 리스크 검증과 학습이 같은 작업이 된다.
