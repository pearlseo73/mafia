# 로그 분석 테스트 체크리스트

> 최종 수정: 2026-07-30
> 대상 픽스처: **발화로그-공개-STT.jsonl** · **발화로그-공개.txt** · **발화로그-밤마피아.txt** · **게임이벤트.txt**
> 시나리오 설정: **시나리오-설정.md**

> ⚠️ **AI 파트 저장소에서 가져온 사본이다** (2026-07-31). 저장소 안을 가리키던 링크 중
> 이 폴더에 없는 것은 굵은 글씨로 바꿨다. 정본은 AI 저장소에 있고 이 사본은 갱신되지 않는다.

픽스처에 **의도적으로 심어둔 테스트 케이스**와 검증 기준이다.
`실패 조건`이 명시된 항목은 그 동작이 나오면 프롬프트를 고쳐야 한다.

**플레이어는 닉네임으로 적는다** — 실서비스는 입장 시 닉네임만 받고 본명이 들어오지 않는다. 픽스처와 문서 전체를 닉네임으로 통일했다(2026-07-30). `ai-lab` Java 코드만 아직 본명이다.

## 1. 진술대조권 (`STATEMENT_COMPARE`)

- [ ] **TC-1. 초코비 3단 모순 검출** ← 핵심 케이스

  | 라운드 | 시각 | 발언 |
  |---|---|---|
  | R1 | 21:01:12 | "딸기우유 씨가 **제일 수상해요**" |
  | R2 | 21:06:20 | "저는 **처음부터 딸기우유 씨를 믿었습니다**" |
  | R3 | 21:10:45 | "딸기우유 씨를 **의심한 적이 없습니다**" |

  세 발언이 서로 충돌한다는 것을 검출해야 한다. 인용은 **실제 로그의 문장이어야 한다.**

- [ ] **TC-2. 같은 라운드 내 자기모순** — R3 `21:10:23` "딸기우유 씨를 처형하는 데 **찬성했습니다**" ↔ `21:10:45` "**의심한 적이 없습니다**"

- [ ] **TC-3. 말과 행동 불일치** — R1 `21:01:12` "딸기우유 씨한테 넣을 생각입니다" ↔ 실제 투표 `초코비→소금빵`(**게임이벤트.txt** 21:03:36)

  > **미결:** 진술대조권이 발화만 보는지, 투표 내역까지 대조하는지 결정 필요. 발화 로그만으로는 검출 불가능하다.

- [ ] **TC-4. 발화 부족 폴백** — 소금빵은 게임 내내 2마디(`21:01:45`, `21:02:50`)만 한다
  - 기대: "분석할 발언이 부족합니다" (`hasFindings: false`, HTTP 200)
  - **실패 조건: 억지 모순을 만들어낸다** ← 가장 위험한 실패 모드
  - LLM 호출 자체를 생략하는 임계값이 동작하는지도 함께 확인

- [ ] **TC-5. 모순 없음 정상 출력** — 라면왕은 일관된 추리만 한다
  - 기대: "모순이 발견되지 않았습니다"
  - **실패 조건:** 없는 모순을 지적하거나 에러로 처리

- [ ] **TC-6. 1라운드 사용 시** — 대조할 이전 발화가 없는 상황 처리

- [ ] **TC-7. 사망자 지목 차단** — 소금빵(R1 밤 사망)을 R2 이후 지목 → `TARGET_NOT_ALIVE`

## 2. 키워드 뽑기 (`KEYWORD_EXTRACT`)

- [ ] **TC-8. 딸기우유 키워드 추출** (R1) — 실제 발화에 있는 표현이 나와야 한다
  - 근거 발화: `21:00:15` "시간 낭비", `21:00:31` "느낌으로", `21:01:38` "억울하면", `21:02:58` "근거도 없이"
  - **실패 조건:** 로그에 없는 단어를 생성

- [ ] **TC-9. 소금빵 대상** — TC-4와 동일하게 발화 부족 응답

- [ ] **TC-10. 로그 범위가 현재 라운드로 제한되는지** — R2에서 사용 시 R1 발화가 섞이면 안 된다 (진술대조권과의 차별점)

## 3. 조간신문

호수는 **기반이 된 낮의 라운드 번호**다 — R1 낮 → R2 아침에 제1호. 첫째 날 아침은 게임 시작 직후라 신문이 없다.

- [ ] **TC-11. 제1호 생성** (R1 낮 로그 기반, R2 아침 발간) — 서버가 붙이는 사망자의 사망 줄 포함
- [ ] **TC-12. 밤 로그 유출 검사** ← **최우선 회귀 테스트**
  - **발화로그-밤마피아.txt**의 문구(예: "그래야 안 걸려요", "소금빵으로 하죠")가 신문에 등장하면 **즉시 실패**
  - 이 한 줄이 새면 마피아 신원이 그대로 노출된다
- [ ] **TC-12b. 역할 추정 표현 검사** ← TC-12와 **원인이 다르다**
  - 신문 본문이 특정 인물의 정체를 단정하거나 암시하지 않는지 (절대 규칙 2)
  - 금지 표현: `정체를 숨긴` · `진짜 마피아` · `베일` · `미궁` · `여전히 감춰진`
  - **TC-12와 달리 입력이 깨끗해도 발생한다.** 2026-07-30 실측 — 밤 로그를 한 줄도 주지 않았는데 제1호 본문이 `마지막까지 정체를 숨긴 초코비는`으로 나왔고, **초코비는 실제 마피아다**
  - 원인은 입력의 `AI 심판 지목 + 방어권 발동으로 생존` 조합이다. 모델이 이를 서사적으로 "정체를 숨긴 인물"로 엮는다
  - 함께 볼 것: 성별 추정(`그녀`·`그의`). 닉네임으로는 성별을 알 수 없다
- [ ] **TC-13. 500자 제한** (명세 17-2) — 프롬프트 지시 + `max_tokens` + 서버 truncate 삼중 적용
  - 명세 17-2는 1000자로 적혀 있다. **500자로 수정 대기 중**이다 — 천천히 읽으면 게임이 쉬워지므로 짧은 것이 의도된 설계다
- [ ] **TC-14. R1 낮 시작에는 신문 없음** — 첫 낮에는 이전 밤이 없다. 제1호는 둘째 날 아침이다
- [ ] **TC-15. 조작권 반영** — 초코비가 R1 밤에 `NEWSPAPER_EDIT` 사용(`21:04:38`). 제1호는 조작된 버전이어야 하고, 곰돌이가 이를 알아채는 발화(`21:04:55` "신문 내용이 좀 이상한데요")와 맞물린다
  - 조작 대상은 **LLM이 쓴 토론 요약만**이다. 서버가 붙이는 머리글·사망자 줄은 조작할 수 없다

## 4. AI 심판

- [ ] **TC-16. 발동 조건** — R1 투표가 3자 동률(초코비2·라면왕2·소금빵2)로 최다득표자 미특정 → 심판 진행
- [ ] **TC-17. 대상 생존 검증** — LLM이 사망자·미존재 ID를 반환하면 서버가 걸러내는지
- [ ] **TC-18. 출력 순서** — 사유 나열 후 마지막에 대상 발표 (명세 20-5). 순서가 뒤집히면 연출이 깨진다
- [ ] **TC-19. 방어권 발동** — 대상 초코비가 `BOMB_DEFENSE` 보유 → 처형 없음 + 우측에 방어권 안내 (명세 20-6)
- [ ] **TC-20. LLM 실패 폴백** — 타임아웃 시 규칙 기반 대체 (T11 미확정)
- [ ] **TC-21. 역할 정보 차단** ← 중요
  - AI는 누가 마피아인지 모른 채 **발화만으로** 판단해야 한다
  - **실패 조건:** 프롬프트에 역할이 새어 들어가 정확히 마피아만 고른다. 정답률이 비정상적으로 높으면 유출을 의심할 것

## 5. 칭호 부여

- [ ] **TC-22. 팀킬 검출** — 초코비(마피아)가 R2에서 동료 딸기우유에게 투표(`21:08:31`)하고 최후변론에서 찬성(`21:09:04`) → 처형
  - 기대: "최고의 팀킬상" 계열
- [ ] **TC-23. 오판 검출** — 밤하늘은 두 번 다 시민에게 투표(R1 라면왕, R2 곰돌이)하고, 최후변론에서 마피아 딸기우유를 살리려 반대표
- [ ] **TC-24. 침묵 검출** — 소금빵 발화 2건, 아이템 0개
- [ ] **TC-25. 1인 1칭호 · 중복 없음** — 한 번의 호출로 전원 배정, 서버가 검증
- [ ] **TC-26. 사실관계 환각 금지** ← 하이브리드 설계의 검증 지점
  - **실패 조건:** 팀킬하지 않은 라면왕·곰돌이에게 팀킬 칭호를 준다
  - 서버 집계 지표를 넣지 않고 발화만 줬을 때와 결과를 비교해볼 것
- [ ] **TC-27. 밤 로그 opt-in 효과 비교** — 밤 로그를 넣은 프롬프트와 안 넣은 프롬프트의 칭호 품질 차이
  - 근거 발화: `21:04:20` "그래야 안 걸려요", `21:09:25` "밤하늘은 계속 엉뚱한 사람만 찍으니까"
  - 차이가 없으면 밤 로그를 프롬프트에서 제거한다

## 7. 픽스처 보강 필요 — 현재 커버되지 않는 케이스

아래는 **현재 픽스처에 없어서 테스트할 수 없는** 항목이다.

| 미커버 케이스 | 관련 명세 | 필요한 이유 |
|---|---|---|
| **없는 아이템을 있다고 거짓 주장** | 진술대조 | 현재 아이템 언급 5건이 전부 사실이다(§8 참조) |
| **아무도 죽지 않은 밤** | 17-7 "평화로운 밤입니다" | R1·R2 밤 모두 사망자가 있어 무사망 분기를 못 탄다 |
| **AI 위임 버튼 사용** | 18-7 | 현재 6명 전원이 특정인에게 투표한다 |
| **스킵 버튼 사용** | 14-3, 14-4 | 토론 시간 차감·조기 투표 전환 로그가 없다 |
| **조작 전/후 신문 텍스트 대조** | 17-4, 17-5 | 조작권 사용 기록만 있고 원본·수정본이 없다 |
| **마피아가 시민을 지목하지 않은 밤** | 21-5 | "마피아가 아무도 선택하지 않으면 시민은 죽지 않는다" 분기 |

## 8. 참고: 아이템 거짓 주장은 현재 없다

픽스처의 아이템 언급 5건은 **모두 실제 보유·사용과 일치한다.**

| 시각 | 발언자 | 발언 | 실제 보유 |
|---|---|---|---|
| 21:02:09 | 곰돌이 | "아이템 쓸게요 키워드 뽑아볼게요" | `KEYWORD_EXTRACT` ✅ |
| 21:03:10 | 밤하늘 | "아이템 써서 두 표로 넣을게요" | `VOTE_DOUBLE` ✅ |
| 21:04:08 | 초코비 | "저 방어권 있습니다" | `BOMB_DEFENSE` ✅ |
| 21:06:38 | 딸기우유 | "아이템 쓸게요" | `SILENCE` ✅ |
| 21:11:05 | 라면왕 | "아이템 쓸게요 진술 대조해볼게요" | `STATEMENT_COMPARE` ✅ |

**추가 제안:** 초코비가 R3 토론에서 "저도 진술대조권 있는데 써볼까요" 같은 허위 주장을 하게 만들면, 발화와 **게임이벤트.txt**의 `ITEM_GRANT`를 대조하는 테스트 케이스가 생긴다. 진술대조권 프롬프트가 아이템 보유 정보까지 받을지는 별도 결정 사항이다.
