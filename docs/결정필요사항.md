## 회의 안건 (우선순위 순)

착수를 막고 있는 순서대로 나열했다. **T1~T3까지 정해지면 AI 파트는 바로 시작할 수 있다.**

- [ ] **T1** 개인정보 — 음성 텍스트가 외부 서버로 전송되는 사실의 고지·동의 절차
- [ ] **T2** 지원 브라우저를 Chrome/Edge로 한정
- [ ] **T3** 밤 마피아 발화를 저장할 것인가
- [ ] **T4** 낮 투표 집계 규칙 (AI 위임 표 처리)
- [ ] **T5** AI 심판 구간 시간 (명세 누락)
- [x] **T6** AI 아이템 분석 결과의 공개 범위 — **✅ 확정: 사용자 본인만** (명세 문구 추가 필요)
- [ ] **T7** LLM 호출 중 국면 전환 시 아이템 소모 처리
- [ ] **T8** 토론 잔여 시간 부족 시 아이템 사용 차단 여부
- [ ] **T9** 결산 화면 + 칭호 부여 (Task 22) 신설
- [ ] **T10** 얼굴 분석 값의 계산 주체와 위조 감수

## A. 팀 논의 필요

### T1. 개인정보 — 음성 텍스트 외부 전송 고지

| | |
|---|---|
| 배경 | Chrome의 Web Speech API는 온디바이스가 아니라 **오디오를 구글 서버로 전송**해 인식한다. 얼굴·음성은 생체정보로 개인정보보호법 적용 대상이다. |
| 결정할 것 | ① 고지·동의 절차를 어디에 넣을지 (랜딩 / 닉네임 모달 / 권한 요청 시점) ② 문구 ③ 발화 원문을 MySQL에 저장하지 않는 방침 확정 |
| 권고 | 7-1 카메라·마이크 권한 요청 시점에 함께 고지. 발화 원문은 **Redis에만** 두고 TTL로 소멸, MySQL에는 집계 결과만 저장 |
| 영향 | 프론트(동의 UI), 백엔드(DB 스키마), 전체 |
| 막고 있는 것 | **STT 수집 전체** — 여기가 안 정해지면 AI 기능 4종 모두 착수 불가 |

### T2. 지원 브라우저 한정

| | |
|---|---|
| 배경 | `webkitSpeechRecognition`은 Chrome/Edge 전용이다. Firefox 미지원, Safari 부분 지원. |
| 결정할 것 | Chrome/Edge 한정을 공식화하고 랜딩에 안내할지, 아니면 미지원 브라우저에서도 STT 없이 플레이 가능하게 할지 |
| 권고 | **Chrome/Edge 한정 명시.** STT 없이 플레이하면 신문·심판·아이템이 전부 빈 껍데기가 되므로 부분 지원은 실익이 없다 |
| 영향 | 전체, QA, 시연 환경 |

### T3. 밤 마피아 발화 저장 여부

| | |
|---|---|
| 배경 | 21-2에 따라 밤 마피아 음성은 시민에게 전송되지 않는다. 이 발화를 로그로 남기면 **칭호 부여에만** 쓸 수 있다(게임 종료 = 역할 공개 시점이므로 유출 아님). |
| 결정할 것 | 저장할 것인가 |
| 권고 | **저장한다.** 쓰기 비용이 사실상 0(키 하나 추가)이고, "낮에 동료 마피아를 팔아넘긴" 류의 칭호는 밤 로그 없이 만들 수 없다. 단 밤은 30초 + 21-4 선착순 지정이라 실제 발화량은 적으므로, 칭호 프롬프트에서 opt-in으로 넣고 효과 없으면 프롬프트에서만 제거 |
| 주의 | 저장하더라도 **키를 분리**해야 한다(`utt:{roomId}:mafia:{n}`). 한 리스트에 담고 조회 시 필터링하면 필터 누락 = 마피아 신원 노출 |
| 영향 | 개인정보(T1), 백엔드 |

### T4. 낮 투표 집계 규칙

| | |
|---|---|
| 배경 | 18-7의 AI 위임 표는 특정 플레이어에게 가는 표가 아니다. 18-8은 "최다 득표자가 특정되지 않으면 AI 심판"이라고만 한다. |
| 문제 | 6명 중 1명만 A에게 투표하고 5명이 AI 위임한 경우 — A가 최후변론인가, AI 심판인가? |
| 권고 | **"AI"를 하나의 후보로 취급.** 최다 득표가 AI면 AI 심판 / 플레이어 간 동률이면 AI 심판 / 단독 최다 플레이어의 표가 AI 위임 수보다 많으면 최후변론. 다수가 위임했는데 1표짜리가 변론대에 서는 상황을 막는다 |
| 영향 | 백엔드(집계 로직), 기획(밸런스) |
| 막고 있는 것 | AI 심판 발동 조건 구현 |

### T5. AI 심판 구간 시간

| | |
|---|---|
| 배경 | 13-2가 토론 3분 / 투표 30초 / 최후변론 30초 / 밤 30초만 정의하고 **AI 심판 구간이 빠져 있다.** |
| 결정할 것 | 구간 시간 (논의 중 약 30초로 이야기됨) |
| 권고 | **30초 확정.** 20-4·20-5의 연출(얼굴 순차 표시 → 사유 나열 → 대상 발표)이 LLM 스트리밍 지연을 흡수하는 구조라 30초면 충분하다 |
| 영향 | 백엔드(서버 타이머, 13-5·14-5), 프론트(연출) |

### T6. AI 아이템 분석 결과의 공개 범위 — ✅ 확정

| | |
|---|---|
| 배경 | 15-4/15-5는 "아이템 사용공지를 텍스트로 전달"한다고만 한다. `진술대조권`·`키워드 뽑기`의 **분석 결과**를 누가 보는지가 정의되지 않았다. |
| **확정** | **아이템을 사용한 본인만 대상자의 분석 결과를 볼 수 있다.** 사용했다는 사실만 전체 공지(15-5) |
| 근거 | 진술대조권은 시민 전용 아이템이므로, 결과를 전체 공개하면 마피아가 정보를 공짜로 받는다 |
| 남은 일 | **기능명세서에 문구가 없다** → Task 16에 항목 추가 필요 (§아래 제안 문구) |
| 영향 | 프론트(결과 표시 범위), 백엔드(WS 개별 전송) |

**명세서 추가 제안 문구**

```
16-11. 진술대조권과 키워드 뽑기의 분석 결과는 해당 아이템을 사용한 본인에게만 표시한다.
       사용 사실은 시스템 로그로 전체에게 공지한다.
```

> 스펙은 이미 다른 곳에서 같은 표현을 쓰고 있다 — 17-3 "마피아에게만", 18-5 "본인에게만". 관례로 유추되지 않는 누락이므로 명시가 필요하다.

### T7. LLM 호출 중 국면 전환 시 아이템 소모 처리

| | |
|---|---|
| 배경 | 16-6은 *"대상 지정 **대기 중** 투표로 넘어가면 사용 취소"*까지만 정의한다. **대상 지정은 끝났고 LLM 호출이 진행 중인 상태**에서 투표로 전환된 경우가 공백이다. |
| 결정할 것 | 아이템을 소모 처리하고 결과를 늦게라도 보여줄지, 취소하고 아이템을 돌려줄지 |
| 권고 | **대상 지정 완료 = 사용 확정(사용 완료), 결과는 늦게 도착해도 표시.** 아이템을 썼는데 결과가 사라지는 것이 유저 체감상 최악이다 |
| 영향 | 기획, 백엔드(아이템 상태 머신), 프론트 |

### T8. 토론 잔여 시간 부족 시 아이템 사용 차단

| | |
|---|---|
| 배경 | `진술대조권`·`키워드 뽑기`는 **토론 중에만** 쓸 수 있어 LLM 지연이 그대로 노출된다. 조간신문·AI 심판과 달리 연출로 가릴 수 없다. |
| 결정할 것 | 토론 잔여 시간이 응답 목표 시간보다 짧으면 사용 자체를 막을지 |
| 권고 | **막는다.** T7과 함께 적용해야 "썼는데 못 봤다"가 안 생긴다. 임계값(예: 잔여 15초 미만)은 실측 후 조정 |
| 영향 | 기획, 프론트(버튼 비활성 조건 — 16-4의 "사용 불가" 상태 활용) |

### T9. 결산 화면 + 칭호 부여 (Task 22 신설)

| | |
|---|---|
| 배경 | 칭호 부여를 게임 종료 후 결산으로 하기로 정했으나 **명세서에 결산 화면 자체가 없다.** |
| 결정할 것 | ① Task 22로 명세 추가 ② 결산 화면 구성 ③ 칭호를 1인 1개로 할지 ④ 결산 후 흐름(재시작 / 대기실 복귀 / 랜딩) |
| 권고 | 1인 1칭호(중복 없음), 결산 화면은 2~5초 로딩 허용. 게임당 LLM 1회 호출이라 비용·지연 부담이 가장 적은 기능이다 |
| 영향 | 기획(신규 명세), 프론트(신규 화면), 백엔드(지표 집계) |

### T10. 얼굴 분석 값의 계산 주체

| | |
|---|---|
| 배경 | 19-3이 "별도 서버 없이 클라이언트에서 처리"로 정해져 있다. 그런데 각 클라이언트가 각자 계산하면 **6명이 서로 다른 동요 지수를 본다.** |
| 권고 | **최후변론 대상자 본인의 클라이언트가 로컬 카메라 스트림으로 계산 → 서버로 전송 → 전원에게 브로드캐스트.** 전원이 같은 값을 보고, CPU 비용도 1대에만 발생한다 |
| 논의 필요한 지점 | 대상자가 브라우저를 조작해 **값을 위조할 수 있다.** 다만 이 지표는 19-4 찬반 투표에 직접 영향이 없는 연출값이므로 감수 가능하다고 본다 — 팀이 동의하는지 확인 필요 |
| 대안 | 방장 클라이언트가 수신 스트림으로 계산 → 위조는 막지만 방장 사망·이탈 시 승계 로직이 추가된다 |
| 영향 | 프론트, 백엔드(WS 이벤트) |

### T11. AI 심판 LLM 실패 시 폴백

| | |
|---|---|
| 배경 | LLM 호출이 타임아웃·에러로 실패하면 처형 대상이 결정되지 않는다. |
| 결정할 것 | 규칙 기반 대체(예: 지목당한 횟수 최다 / 발화량 최저) / 무작위 / 아무도 죽지 않음 |
| 권고 | **규칙 기반 대체 + 시스템 알림.** "아무도 죽지 않음"은 AI 심판을 회피 수단으로 악용할 여지를 준다 |
| 영향 | 기획(밸런스), 백엔드 |

### T12. GMS 호출량·비용 한도

| | |
|---|---|
| 배경 | 게임 1판 기준 LLM 호출은 **라운드당 조간신문 1회 + AI 심판 발동 시 1회 + 아이템 사용 시 n회 + 게임당 칭호 1회**다. 동시 진행 방이 늘면 비례해 증가한다. |
| 결정할 것 | ① API 키 관리 주체 ② rate limit 도달 시 동작 ③ 동시 게임 수 상한 |
| 영향 | 인프라, 백엔드 |

## B. AI 담당자 단독 결정

팀 논의 없이 진행하되, 결과는 공유한다.

### 이미 정한 것

| 항목 | 결정 |
|---|---|
| 얼굴 분석 라이브러리 | **`@vladmandic/face-api`** — 원본 `face-api.js`(0.22.2)는 방치되어 tfjs 1.7 고정 + Vite/ESM에서 깨진다. API 호환 포크 |
| 모델 로드 범위 | `tinyFaceDetector` + `faceExpressionNet` **2종만**. landmark68·recognition 미사용 (~520KB) |
| 모델 서빙 | `public/models/` 정적 서빙 (CDN·외부 의존 없음) |
| 모델 로드 시점 | 낮 투표(30초) 진입 시 선행 로드. 최후변론 시작 후 로드하면 초반이 빈 화면 |
| 동요 지수 산식 | EMA(alpha 0.15) + 변론 첫 3초 베이스라인 대비 변화량 |
| 추론 빈도 | 10fps, `inputSize` 224 → 드랍 시 160 하향 |
| Redis 키 구조 | `utt:{roomId}:public` / `utt:{roomId}:mafia:{n}` (ZSET, score=timestamp) |
| 아이템 로그 범위 | 진술대조권 = **전체 라운드**(모순 탐지) / 키워드 뽑기 = **현재 라운드**(요약) |
| 환각 방어 | 발화 수가 임계값 미달이면 **LLM을 호출하지 않고** 서버가 "분석할 발언이 부족" 응답 |
| 칭호 생성 방식 | **하이브리드** — 서버가 지표 집계(팀킬 수, 침묵 라운드, 투표 적중 등) → LLM은 칭호명·대사만 창작. 순수 LLM 창작은 팀킬 안 한 사람에게 팀킬상을 준다 |
| 칭호 호출 방식 | 전원을 **1회 호출**로 배정(JSON 배열) → LLM이 중복을 스스로 회피, 서버가 검증 후 1회 재시도 |
| 신문 길이 제한 | **`max_tokens`(≈450자) + 서버 500자 검사.** 프롬프트에 글자수를 적어도 지켜지지 않았다 (07-30 실측) |
| 신문 생성 시점 | **낮 결과 확정 직후.** 17-1(투표 시작)대로면 동률·심판·방어권·밤 사망이 전부 생성 뒤에 일어난다 → 명세 수정 요청 |
| 신문 조립 방식 | **2단** — 밤에는 머리글+본문만, 아침에 서버가 사망자 줄을 앞에 붙인다. 처형·역할 조작이 구조적으로 무효화된다 |
| 신문 사전 열람 범위 | **조작권 소지자 한 명만.** 마피아 전원에게 주면 시민이 상시 불리해진다 |
| AI 심판 출력 구조 | 스트리밍 (사유 → 대상 순서가 20-5와 일치). 대상이 생존 플레이어인지 서버 검증 |
